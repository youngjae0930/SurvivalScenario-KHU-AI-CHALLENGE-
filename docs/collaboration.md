# 협업 기준

## 범위
- 기준 문서: 기획안 v1.2, 기술 설계 초안 v0.2.
- 승인 필요 D01~D09는 임의 확정하지 않는다.
- 현재는 환경 구축 단계이며 게임 시스템과 본격 UI를 구현하지 않는다.

## 역할
- A / GPT-6.1 Sol 활용:
  환경, 게임 코어, 영속 상태, 확률, 동료 판단, 계승, 저장, 통합 담당.
- B / Claude Opus 5.5 활용:
  UI/UX, React 화면, UI 임시 상태, 스타일, 애니메이션, 스토리와 대사 담당.
- 각 담당자는 AI가 만든 코드의 검토, 실행, 커밋에 책임진다.

## 폴더 소유권
- A: src/app, src/domain, src/engine, src/storage, src/content/rules.
- B: src/ui, src/assets, src/content/texts.
- src/contracts: A가 관리하고 A/B 합의 후 변경한다.
- 설정 파일, 패키지 파일, main.tsx, 앱 연결 파일은 A가 통합 관리한다.
- index.css의 초기 연결은 A, 이후 전역 스타일은 B에게 인계한다.
- 테스트는 대상 모듈 가까이에 두고, src/test에는 공통 지원 코드를 둔다.

## 경계
- 엔진은 React, DOM, localStorage, 현재 시각을 직접 참조하지 않는다.
- 엔진의 난수는 명시적으로 전달된 PRNG 상태 등으로 통제한다.
- UI는 공개 계약을 통해 데이터를 받고 명령을 전달한다.
- UI는 확률, 비용, 잠금 조건, 동료 판단을 자체 계산하지 않는다.
- UI는 엔진과 저장소를 직접 호출하지 않는다.
- 영속 상태와 저장 조정은 앱 계층, 확인창과 애니메이션 상태는 UI가 맡는다.
- 계산된 다음 상태는 저장 성공 후 확정한다.
- 규칙 데이터와 문구는 ID로 연결한다.
- 문구 담당자는 규칙 수치, 조건, ID를 임의 변경하지 않는다.

## 계약과 통합
- UI 구현 전 ViewModel, 명령, 오류, 컴포넌트 입력 계약을 합의한다.
- 목 데이터도 같은 계약을 사용한다.
- 계약 변경 시 사용처, 목 데이터, 테스트를 함께 확인한다.
- 공개 계약 없이 상대 영역의 내부 파일에 직접 의존하지 않는다.

## Git 운영
- main은 검증된 통합 기준으로 유지한다.
- 기능별 짧은 브랜치를 사용하고 작은 PR로 통합한다.
- PR에 변경 파일, 계약 변경, 검증 결과를 기록한다.
- 패키지 추가와 공통 설정 변경은 사전 합의한다.
- package.json과 package-lock.json을 함께 관리한다.
- node_modules와 dist는 커밋하지 않는다.

## 환경 기준
- Node.js: 24.22.1
- npm: 11.19.1
- 패키지 관리자: npm
- 의존성 재현: npm ci
- 정확한 프로젝트 의존성 버전은 package-lock.json을 기준으로 한다.
- 기존 린터 Oxlint를 유지한다.

## 검증
- 개발 서버: npm run dev
- 테스트: npm run test:run
- 린트: npm run lint
- 빌드: npm run build
- 빌드 미리보기: npm run preview
- 린트, 타입 검사, 빌드, 미리보기는 아직 최종 확인 전이다.
