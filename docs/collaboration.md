| src/domain | 내부 게임 타입·검증·불변식 |
| src/engine | 순수 게임 규칙·판정·진행·동료·계승 계산 |
| src/storage | 영속 입출력·디코더·호환·복원 |
| src/content/rules | 수치·조건·설문 매핑·행동 정의 |
| src/content/texts | 상황·선택명·결과·관계 반응·안내 문구 |
| src/assets / public | 번들 자산 / URL로 제공할 정적 자산 |
| src/test / 대상 옆 테스트 | 공통 테스트 지원 / 기능별 검증 |

`main.tsx`·`App.tsx`는 조립을 맡고 게임 규칙을 넣지 않는다. 현재 폴더를 활용하고 큰 경로 이동은 하지 않는다. 신규 하위 폴더는 기능과 함께 생성한다.

## 구현 경계

- UI는 contracts만 통해 앱을 호출한다. 엔진·저장소·규칙 JSON을 직접 읽거나 비용·판정을 복제하지 않는다.
- 앱은 규칙/문구를 묶어 표시 모델을 만들고 현재 상태·previewToken·동기 잠금·구독을 관리한다.
- 엔진은 React·DOM·localStorage·현재 시각 없이 명시적 난수 상태로 계산한다.
- 문구는 ID로 규칙과 연결한다. 스토리 작성이 규칙 수치/효과 변경을 의미하지 않는다.
- 공개 계약 변경은 Codex가 영향 검토 후 버전·사용처·fixture·문서·테스트를 함께 수정한다. 별도 모델의 동의를 기다리지 않는다.
- 영속 모드는 저장 성공 후 화면을 확정하며 재시도에서 재추첨하지 않는다. 메모리 플레이는 별도 능력/성공 의미를 계약과 화면에 명시하고 영속 저장으로 표현하지 않는다.
- 미정 정책은 해당 기능을 구현할 때만 확인하고 다른 독립 기능은 계속 진행한다.

## 검증과 운영

각 기능은 화면·문구·코어 연결·검증까지 묶어 완료한다. 코어 테스트만으로 플레이 가능을 보고하지 않는다. lint/test/build와 필요한 브라우저 조작을 실제 실행하고 결과·미검증 범위를 남긴다. 단계 완료 시 전체 기능 기준 추정 퍼센트를 보고한다.

기존 React19/TypeScript7/Vite8/Tailwind4/Vitest5/Oxlint와 npm/package-lock을 유지한다. Node24.22.1·npm11.19.1은 기존 기록 기준이며 환경 변경 시 실제 버전을 확인한다. 새 의존성은 필요성을 검토하고 package.json/lock을 함께 관리한다.

main은 검증된 기준으로 유지하고 기능별 브랜치/PR에는 행동 변화·검증을 기록한다. node_modules/dist/비밀 파일은 커밋하지 않는다. 이번 로드맵 정비에는 커밋·푸시·배포가 포함되지 않는다.

실행 명령: `npm run dev`, `npm run lint`, `npm run test:run`, `npm run build`, `npm run preview`.
