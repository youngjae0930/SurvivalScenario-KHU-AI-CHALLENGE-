# 선택 결과에 따른 신뢰와 이별 갈등

2026-10-29 사용자 수정: 신뢰80은 구조에 한정하지 않고, 서로 다른 의지가 **이별로 이어지는 상황**에서 동행을 유지하는 기준이다. 단순 의견 차이는 이별 조건이 아니다. 신뢰는 선택의 이득/손해를 종합해 그 크기에 따라 소폭 증감한다. 기존 양보 고정+10은 새 회차에서 대체한다.

## 게임에서의 변화

동료가 함께 있을 때 모든 실제 선택 결과를 평가한다. 체력 회복·스트레스 감소·부상 치료·자원/무기 획득·접근/자료/연락망/경로 확보와 그 반대 손실을 합산한다. 실제 상한 적용 뒤 변화만 계산하며 이미 가진 정보나 버린 초과 물자는 이득으로 세지 않는다. 자원 소비와 회복을 함께 보므로 치료 도구를 썼다는 이유만으로 손해로 단정하지 않는다.

안정형일수록 신체 안전을, 분석형일수록 자원·정보를 조금 더 크게 평가한다. 콘텐츠가 명시한 이야기 결과는 동료의 해당 성향에 비례해 평가한다(정확히50은 중립). 현재 구조/자기 보존 결과와 동료에 대한 물자 지원을 작성했다. 추천을 따름/거절함·주인공 성향 수치 변화 자체는 신뢰 보상이 아니다. 실패도 실제 피해가 없다면 자동 감점하지 않으며 성공도 소모가 크면 하락할 수 있다. 이탈 중에는 남아 있는 동료 신원의 신뢰를 원격 변경하지 않는다.

초기 조정값은 `src/content/rules/relationship.ts`: 체력10당1, 스트레스20당1, 부상1당3, 물자1당1.5, 치료 도구/무기1당2, 정보1~2 평가 단위다. 신체/자원 가중치는 각 성향에 따라0.75~1.25배, 이야기 가치관은 `(성향−50)/50`에 극 방향을 적용한다. 합계를 대칭 반올림한 뒤 **한 선택당−5~+5**, 최종 신뢰0~100으로 제한한다. 탈출에는 실제 생존 이득5, 치명 부상에는 생존 불가 손실을 반영한다. 이 세부값은 사용자에게 수치별 승인을 받았다는 뜻이 아닌, 요청을 구현하는 초기 밸런스 값이다. 일반 추천 D01의 자원 비교/보류 정책에는 이 점수를 사용하지 않는다.

미리보기는 실제 성공/실패 상태 각각의 신뢰와 근거를 표시한다. 실행은 발생한 결과 한 번만 적용하고 확인/재접속/저장 재시도 때 중복 적용하지 않는다. 결과·결말에 실제 변화와 각 근거의 이득/손해를 표시한다. 한쪽 방향에만 제공되는 극단 선택과 네 선택 고정은 유지한다.

## JSON 확장

manifest의 `trustVersion: "outcome-1"`과 `autonomyVersion: "journey-2"`를 사용한다. 기본 상태 손익은 엔진이 계산하며 이야기의 실제 결과만 choice.relationship에 추가한다. magnitude는 신뢰 직접 증감이 아닌 작은 평가 단위다. 엔진은 사건 번호·선택명·성향 변화에서 이야기 결과를 추측하지 않는다.

```json
"relationship": {
  "success": [
    {"kind":"value","axis":"affect","pole":"right","magnitude":2,"reason":"남은 사람을 돕는 목표 달성"}
  ],
  "failure": []
}
```

동료에게 실제로 제공한 도움/손해는 `{"kind":"support","magnitude":2,"reason":"동료에게 물자를 나누어 함께 회복함"}`처럼 명시한다. 상태 변화에 이미 포함된 이득을 중복 작성하지 않는다. value의 magnitude는1~3, support는−3~3이며 각 결과는 최대5개다. 미작성한 이야기 이득을 자동 생성하지 않는다.

이별은 실제로 다른 길을 가게 되는 중요한 갈등만 다음처럼 지정한다. 현재 구조 관련 세 장면을 이 형식으로 전환했고, 이동·조사·자원 목표도 같은 형식을 사용한다. 새 이별 이야기를 무단 생성하지 않았다.

```json
"autonomy": {
  "conditions": [],
  "conflicts": [
    {"playerGoalId":"leave","companionGoalId":"investigate","reason":"동료는 자료를 포기하지 않고 남으려 한다."}
  ],
  "reunion": {"locationTags":["safe-hub"],"minVisits":1,"conditions":[]}
}
```

playerGoalId/companionGoalId는 그 사건의 실제 서로 다른 목표여야 한다. 현재 동료의 유효 추천과 주인공의 선택이 해당 조합일 때만 이별 후보가 된다. 판단 보류는 이별 의지로 취급하지 않는다. **행동 전 신뢰80 이상**은 동행을 유지한다. 이 기준은 이별 방지이며 파견 수락60과 별도다. 신뢰 변화가 현재 명령 수락이나 동행 판정을 소급 취소하지 않는다. 재회는 기존 태그/방문 조건을 사용하고 경로에 강제 삽입하지 않는다.

## 저장·호환과 검증

신규 팩 catalog-companion-outcome-1·동행 runtime catalog-companion-outcome-1·계승 runtime catalog-succession-9. 계약0.7.0과 schema6/7/8·단독 runtime3 유지. 직전 팩은 fixture v17로 고정했다. 기존 저장의 양보+10·구조 판단 기준은 원래 팩으로 재생하며 새 규칙을 끼워 넣지 않는다. 최신 규칙은 새 회차에 적용한다.

선택 당시 관계 평가 버전·동료 상태·작성된 결과·각 후보의 실제 상한 적용 신뢰 증감을 기록한다. D08은 후보의 실제 신뢰 효과를 비교해 동료 때문에 효과가 다른 상황을 구분한다. 동료의 존재나 이름만으로는 달라지지 않으며, 관계 효과가 모두0이면 단독/동행도 이 이유로 구분하지 않는다. 저장은 입력부터 실제 결과를 재생해 신뢰/이유 위조를 거부하고 저장 성공 후만 화면을 확정한다.

보호 약속은 후속 사용자 요청으로 개발 범위에서 제외했다. 선언/철회나 별도 위반 감점을 추가하지 않는다. 다음은 D09 유동 분량과 두 회차 합계약15분 실측이다.
