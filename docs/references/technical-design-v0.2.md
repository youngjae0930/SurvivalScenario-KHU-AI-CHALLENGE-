2.5.1 판단 기준과 순서
[유지] 사건의 지배 축에 대한 동료 극단 → 유효한 구조 판단 집계 → 동료 성향 방향 → 실행 가능한 기본 후보 순서다.
주인공 성향과 동료 성향을 평균내지 않는다. 현재 trust는 의견이 아니라 대안 개방과 참여에 사용한다.
[명확화] 실행 가능성은 물리 조건과 주인공 극단 잠금을 분리한다. 물자가 없어서 불가능한 추천은 다른 후보로 넘길 수
있다. 그러나 낮은 trust 때문에 제지 대안이 잠긴 것을 물리 불가로 간주하여 동료가 주인공에게 동의하는 의견으로 바

현재 맥락 후보 제한 → 근거 tier 선택 → 선호 목표 선정 → 물리적으로 가능한 방식 탐색
→ 주인공 행동 목록과 연결 → 최종 추천 1개·목표·근거 고정

2.6.1 개념 분리
행동 목표: 무엇을 하려는가.
실행 주체: 누가 선행 위험 행동을 하는가. 주인공 또는 동료.
협력: 동료가 선택한 행동에 참여·지원하는가.
위험 파견: 플레이어가 동료를 선행 위험 실행 주체로 확정하는가.
독자 행동: 동료가 명령과 무관하게 다른 목표로 행동하는가.
협력과 파견은 같은 개념이 아니다. ‘주인공 직접 실행+동료 지원’도 가능하다. 동료가 협력한다고 자동으로 파견된 것으
로 기록하지 않는다.
2.6.2 약속의 범위와 입력 [승인 필요 D03]
기획안은 E05/E09/E10에 보호 약속을 제공하지만 약속 지속 범위·철회 시점을 완전히 정하지 않았다.
권고안: 사건 단위로 한 번 약속 여부를 정하고, 그 사건의 실행 확정까지만 유효하게 한다. 별도 전역 평판·회차 전체 약
속은 추가하지 않는다.
사건 도입에서 보호 약속 여부를 선택한다. 확인 전 입력은 임시다.
선택 확인에는 약속을 지켰는지와 주체·공동 위험·예상 신뢰 변화를 함께 표시한다.
실행 확정 전에는 행동 선택을 취소할 수 있다. 사건 수준에서 이미 확정한 약속은 확인창을 닫는 것만으로 사라지지
않는다.
약속 자체를 언제 확정할지와 실행 전 철회 허용 여부는 사용자 승인 대상이다. 권고는 사건에서 명시적으로 확정한
약속은 해당 사건 동안 유지하는 방식이다.
행동 확정 후 약속 이행·위반을 기록하고 다음 사건에서 활성 약속은 해제한다. 이력은 history에 남긴다.
약속을 별도 확정하는 UI를 채택하면 그 시점의 저장은 전투·선택 해결이 아닌 약속 메타데이터 커밋이다. 비용·난수·성
향·신뢰·집계를 바꾸지 않는다. 새로고침으로 이미 한 약속이 삭제되지 않게 한다. 이 UI 정책을 승인하지 않는다면 전부
실행 입력에 묶는 대안도 가능하지만, 그 경우 자유로운 사전 철회가 배신 체험을 약화시킬 수 있음을 기록한다.
2.6.3 위험 파견 허용 조건 [승인 필요 D03]
권고안은 E05 탐사·돌입, E09 돕기, E10 구조의 명시된 위험 행동에 한해 동료 선행 실행 옵션을 검토하는 것이다. 확정

2.8.2 사건·확인·결과 화면
사건 화면은 상황, 동료 의견, 선택, 상태, 최근 결과를 유지한다. E02/E09/E10에는 구조 대상 반응과 동료의 동의·유보
·반대 이유를 적어도 한 줄 제공한다.
선택 확인은 의도·대상·주체 → 요구 조건·비용 → 알려진 위험·확률 → 동료 참여·기여 → 약속 위반·독자 행동 경고 순이
다. 실행 전 취소는 자유이며 선택 결과를 선공개하지 않는다. 이미 별도로 확정한 사건 약속까지 취소된 것으로 간주하
지 않는 D03 권고와 구분한다.
결과는 의도 → 성패/확정 → 실제 상태 증감 → 신뢰 원인 → 이후 영향 순이다. mechanical·relationship·expressive를
구분한다. 관련 payoff가 없는 선택에 장기 영향 알림을 표시하지 않는다.
모바일 단일 열과 데스크톱 보조 상태 영역을 지원한다. 잠금·위험은 색상+텍스트, 확인창 초점 이동·취소 후 초점 복귀·
키보드 실행을 지원한다.
2.8.3 2회차 종료의 과거-현재 비교 [승인 필요 D06]

확률식의 traitWeights는 위험 행동의 성공률 보정 가중치이지 동료 행동의 효용 점수가 아니다. 이를 이유로 Utility
AI라고 부르지 않는다. 현재 방식은 결정적 후보 필터·우선순위 테이블이며, 유틸리티 점수화를 추가하려면 핵심 판단
규칙 변경이므로 별도 승인 대상이다.

규칙형 판단으로 명칭을 통일하는 것은 새 기능 승인이 아니라 현재 설계 설명의 정정이다. Utility AI라는 이름을 유지하
려고 효용 점수 시스템을 추가하지 않는다.
4.4 최종 검토 결론
유지할 중심 구조: 순수 엔진의 결정적 판단 → 선택 전 동일 스냅샷 → 단일 행동의 원자적 해결 → 저장 성공 후 UI 확정
→ 실제 근거로 회차 간 연결 설명.
이번에 고친 핵심: 추천·참여·주체를 분리하고, traits/counts와 회고 기록의 역할을 구분했으며, 저장 실패 재시도와 종
료 비교의 입력 보존을 일관되게 정리했다.
사용자 검토 후 확정할 핵심: 중앙값·추천 방식·극단 후보 개방(D01~D02), 보호 약속·파견·피해(D03), E07 미정값
(D04). 이 사항들이 결정되기 전까지 완료·무충돌·테스트 통과를 선언하지 않는다.
