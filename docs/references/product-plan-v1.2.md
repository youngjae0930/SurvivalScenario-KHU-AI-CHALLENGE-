[문단 3] 0. 제작 목표

[문단 5] 목표는 ‘한 회차의 선택이 성향을 만들고, 그 인물이 다음 회차의 동료로 내 선택에 개입한다’는 경험을 실제 작동시키는 것이다. 통합조사 검토를 반영한 v1.2의 제작 규칙은 아래와 같다. 수치 조정은 가능하지만, 조정 시 버전을 올리고 테스트를 다시 수행한다.

[문단 6] 1. 게임 개요와 완료 범위

[문단 7] 주인공은 좀비 발생 도시에서 구조 차량에 도달하려 한다. 안전한 탈출과 위험한 연구 자료 회수 사이에서 판단하며 성향이 변한다. 다음 회차에서는 직전 주인공의 성향과 주요 판단 방식을 반영한 ‘잔상 동료’가 함께한다. 이 명칭은 판단 방식이 이어진다는 설계 용어이며, 유령·사망 경험자·부활한 인물을 뜻하지 않는다. 동료는 현재 회차에서 처음 위기를 겪는 살아 있는 별개의 인물이다. 이전 주인공의 죽음이나 실패를 경험하거나 기억하지 않는다.

[문단 8] 1.1 반드시 구현하는 범위

[문단 9] 고정된 사건 슬롯 12개, 슬롯당 기본 선택지 2개. 자유 이동과 무작위 사건 배치는 없다.

[문단 10] 성향 3축, 정신력·스태미나·부상, 소모품 2종, 무기 보유 여부.

[문단 11] 극단 판정 사건 6개. 세 축의 양극을 각각 한 사건에서 검증한다.

[문단 12] 계승 동료 최대 1명. 동료 제안·협력·거부·정해진 독자 행동과 신뢰도.

[문단 13] 결말 3종: 연구 자료와 탈출 / 탈출 / 탈출 실패. 동료 동행 여부는 결말 문구 변형이지 별도 결말이 아니다.

[문단 14] 한 기기의 자동 저장 1슬롯, 직전 회차 계승 기록 1개, 결과 기록 화면.

[문단 15] 목표 회차 길이 15~25분은 테스트 목표이지 보장 시간이 아니다. 2회차 플레이까지 검증한다.

[문단 16] 1.2 이번 범위에서 하지 않는 것

[문단 17] 성장형 근력, 부위별 부상, 동료 개별 체력·인벤토리, 다수 동료, 자유 대화, 생성형 AI 실시간 사건 생성, 전술 전투, 장비 내구도, 계승 인물 보관함, 온라인 계정·동기화, 백신 제조 엔딩을 제외한다. 기술적으로 불가능해서가 아니라 상태 조합·집필·검수량을 통제하기 위해 제외한다. 연구 자료 회수는 향후 백신 서사의 연결점일 뿐 이번 버전에서 백신을 만든다고 서술하지 않는다.

[문단 18] 2. 핵심 충돌의 해소 결정

[문단 19] 1. 극단과 선택권: 지정 사건에서만 행동 목표를 고정한다. 실행 방식 2개는 남긴다. 동료가 주인공을 신뢰하면 더 적극적인 제지로 목표가 다른 대안을 제공할 수 있다. 그 외 사건의 선택은 막지 않는다.

[문단 20] 2. 극단의 비가역성: 극단은 영구 잠금이 아니다. 해당 사건에서는 즉시 철회할 수 없지만, 이후 다른 사건에서 반대 방향 선택으로 수치를 되돌릴 수 있다. 원안의 영구 고정보다 플레이 중 자기 교정과 계승 검증 가능성을 우선한다.

[문단 21] 3. 여러 극단 충돌: 사건별 지배 축 1개만 제한을 결정한다. 다른 축은 확률 보정만 한다. 따라서 서로 다른 축 때문에 모든 선택지가 잠기지 않는다.

[문단 22] 4. 신뢰의 방향 모순: 신뢰도는 ‘동료가 주인공을 믿는 정도’ 하나다. 주인공의 대안 수용까지 양방향 신뢰로 해석하지 않는다. 높은 신뢰에서는 동료가 더 적극적으로 제지한다는 규칙으로 대안 개방을 설명한다.

[문단 23] 5. 계승과 인물 정체성: 이전 회차의 판단 기록은 동료 행동을 정하는 게임 시스템의 입력이다. 현재 동료는 죽음을 겪거나 되살아난 존재가 아니다. 이전 결말은 플레이어 기록에만 남기고 동료의 자전적 기억으로 제공하지 않는다. 도입부는 “앞선 플레이의 판단 방식을 반영한, 이번 이야기의 새로운 동료입니다”로 안내한다.

[문단 24] 6. 성향과 과거 기록 충돌: 사건의 지배 축에 대해 극단이면 극단이 우선한다. 일반 범위에서는 같은 주제의 과거 선택 기록이 동료의 의견을 우선 결정한다.

[문단 25] 7. 물리적 잠금과 극단 강제 충돌: 극단 실행 방식 중 최소 하나에는 물자 요구를 두지 않는다. 저자원 상태에서도 손실을 감수한 시도가 가능하다. 물리 조건으로 잠기는 선택과 별도로 최소 하나의 무조건 실행 선택을 제공한다.

[문단 26] 3. 고정 진행 구조와 사건 목록

[문단 27] 회차 생성 → 설문 6문항 → 슬롯 E01~E12 순서대로 처리 → 결말 → 계승 확정. 사건 도중 이동 분기를 만들지 않는다. ‘건물에서 도망’은 해당 탐사 포기를 뜻하며 게임 전체 종료가 아니다. 다른 경로를 거쳐 다음 슬롯으로 합류한다.

[문단 28] 각 사건은 기본 선택 2개를 가진다. 극단 사건은 지정 극에 실행 방식 2개를 작성한다. 기본 24개+극단 12개+동료 후보 최대 12개+맥락 대체 4개로 행동 정의 상한은 52개다. 선택과 결과는 동일한 문장 단위가 아니다. 위험 선택은 성공·실패 결과를, 확정 선택은 결과 1개를 작성한다. 관계 반응은 필요한 경우 별도 문구를 작성하며 모든 조합의 장면을 새로 만들지는 않는다. 읽은 글 건너뛰기·선택 확인·기록 화면은 별도의 UI 작업으로 산정한다.

[문단 29] 3.1 슬롯별 제작 계약

[문단 30] E01 대피소 출발: 안전 확인 / 지름길. 비극단 튜토리얼. risk 축 -8/+8 중 의미에 맞게 부여. 선택과 결과가 다르다는 점을 설명한다.

[문단 31] E02 편의점: 생존자 돕기 / 물자 우선. 구조 기록을 rescue 또는 self로 저장한다. affect 축 -8/+8은 물자 우선=-8, 돕기=+8로 고정한다.

[문단 32] E03 골목: 먼저 관찰 / 즉시 통과. cognition 축 -8/+8. 확률 판정 튜토리얼.

[문단 33] E04 휴식: 정비 / 동료에게 물자 양보. 단독이면 양보 대신 추가 휴식. 극단 없음.

[문단 34] E05 병원 진입: 탐사 / 우회. 지배 축 risk, 모험 극단만 발동. 모험 극단이면 구역 소탕을 목표로 즉시 돌입 / 도구 활용으로 교체한다. 양쪽 성공은 access=true, 실패는 false. 우회는 false.

[문단 35] E06 병원 이탈: 철수 / 잔여 물자 회수. 지배 축 risk, 안정 극단만 발동. 안정 극단이면 철수를 목표로 짐을 버리고 이탈 / 방어하며 이탈. 극단의 고보상은 추가 전리품이 아닌 피해 회피다.

[문단 36] E07 자료실/외곽 중계기: access=true일 때만 기존 조사와 분석 극단 실행을 제공한다. access=false이면 무기 분해 가동 / 자료 포기로 대체한다. 가동은 weapon=true 요구, weapon=false 소모, stamina -10, data=true, 판정 없음. 포기는 무조건 실행, stamina -5, data 유지다. 외곽 장면에는 분석 극단을 적용하지 않는다. 내부 조사 성공은 data=true, 극단 성공은 추가 supply +1이다. 무기 분해의 목적은 무전 전원·연결 부품 확보로 구체적으로 서술한다.

[문단 37] E08 붕괴 통로: 경로 확인 / 직감으로 건너기. 지배 축 cognition, 직관 극단만 발동. 직관 극단이면 즉시 통과를 목표로 난간 도약 / 잔해 틈 통과. 성공 시 스태미나 보존이 보상이다.

[문단 38] E09 격리 구역: 규칙대로 통과 / 남은 사람 돕기. 지배 축 affect, 이성 극단만 발동. 이성 극단이면 격리 규칙 준수를 목표로 방호 경로 / 위험 물품 폐기. 구조 기록은 변경하지 않는다. 과거 구조 판단은 대사·동료 의견에만 사용한다.

[문단 39] E10 구조 신호/연락망: helpEstablished=true이면 “신호 확인”을 “연락망으로 탈출 통로 확인”으로 교체한다. 비용 stamina -5, affect -8, routeKnown=true, 판정 없음이다. 반대 선택인 구조 시도와 감정 극단은 유지한다. helpEstablished=false이면 기존 신호 확인 / 구조 시도다. 구조 성공 supply +1, 실패는 일반 템플릿을 적용한다. 구조 인물은 동료 슬롯에 추가하지 않는다.

[문단 40] E11 차량 대기소: 정비 / 물자 양보. E04와 같은 회복 규칙. 마지막 선택 전에 상태와 결말 요건을 보여 준다.

[문단 41] E12 탈출로: 새 난수 없이 누적 조건으로 결정한다. 단거리는 stamina>=15, injury<=1이면 성공, 비용 stamina -15. 우회는 routeKnown=true, stamina>=30, injury<=2이면 성공, 비용 stamina -30. 조건 미달 행동은 이유를 표시하고 잠근다. 둘 다 불가능하면 “구조 요청”을 무조건 실행해 탈출 실패/구조 대기로 종료한다. data=true와 탈출 성공이면 자료 회수 결말이다. 이 방식은 본 게임의 누적 판단 강조를 위한 선택이지 조사에서 난수를 금지했다는 의미가 아니다.

[문단 42] E01~E11은 치명 부상이 아니면 다음 번호로 진행하되, 앞선 결정은 맥락별 행동 목록·자원 요구·관계 반응에 남긴다. access는 E07 내부 접근과 그 내부 판정 +5를, helpEstablished는 E10 연락망을, routeKnown은 E12 우회를 결정한다. 재수렴 자체는 결함이 아니다. 어느 행동도 모든 후속 사건을 바꿔야 하는 것은 아니며, 약속한 영향이 실제로 드러나는지를 검수한다.

[문단 43] 4. 상태 정의와 초기값

[문단 44] risk: 정수 0~100, 모험 0 ↔ 안정 100.

[문단 45] cognition: 정수 0~100, 분석 0 ↔ 직관 100.

[문단 46] affect: 정수 0~100, 이성 0 ↔ 감정 100.

[문단 47] mental: 정수 0~100, 초기 70. 0은 사망이 아닌 판정 불이익이다.

[문단 48] stamina: 정수 0~100, 초기 70. 0에서도 무조건 실행 선택은 가능하다.

[문단 49] injury: 정수 0~3, 초기 0. 3이면 행동 종료 후 즉시 탈출 실패 결말. 체력·부위별 상태는 없다.

[문단 50] supply: 정수 0~3, 초기 1. 정비·양보용 공용 물자.

[문단 51] medkit: 정수 0~2, 초기 1. 치료·특정 실행 방식용.

[문단 52] weapon: 불리언, 초기 false. E01 지름길 성공 시 획득. 무기 요구를 명시한 선택에서만 잠금 조건으로 사용한다.

[문단 53] access, data, helpEstablished, routeKnown: 불리언, 초기 false. E02 돕기는 helpEstablished=true를 확정한다. rescue/self 기록은 E02 완료 시 저장한다. 미도달은 null이다.

[문단 54] companion: absent 또는 present. 1회차 absent, 2회차 이후 present. present이면 trust=50으로 시작한다. 동료 성향은 계승값으로 고정되며 회차 중 변하지 않는다. 동료 자체 부상·사망은 없다.

[문단 55] 수치는 매 갱신 후 범위 내로 제한한다. 물자는 부족할 때 선택 불가이며 음수로 제한한 뒤 실행하는 방식은 금지한다. 부상이 끝값에 도달하면 회복 효과를 먼저 포함한 해당 행동의 순수 변화량을 적용한 뒤 종료 여부를 확인한다.

[문단 56] 5. 초기 설문과 성향 변화

[문단 57] 설문은 축당 2문항, 각 답이 -10 또는 +10이다. 출발값은 50에서 답을 합산해 30/50/70 중 하나가 된다. 질문과 성향 방향을 일치시키며 초기 극단은 없다. 이름은 표시명일 뿐 수치에 영향이 없다.

[문단 58] 선택 정의는 주축 변화 -8 또는 +8을 가지며 필요 시 보조 축 하나에 -4 또는 +4를 준다. 회복·최종 사건에는 성향 변화 0도 허용한다. 변화 방향은 행동의 의도에 따라 콘텐츠 데이터에 명시하고 엔진이 문장으로 추측하지 않는다. 성공·실패와 무관하게 의도한 선택의 성향 변화는 동일하다. 판정에는 선택 전 성향을 사용한다.

[문단 59] 극단 경계는 0~22 / 78~100, 경고 범위는 23~30 / 70~77이다. 짧은 사건열에서 정상 플레이로 극단이 발생하도록 조정했다. 설문 완료 직후에는 극단이 없고 경고만 가능하다. 최초 경고 진입 시 설명을 띄우며 극단 진입·해제는 항상 결과 창에 표시한다. 극단 판정은 사건 표시 시점의 값으로 고정한다. 한 선택 후 같은 사건을 다시 열어 상태를 재판정하지 않는다. 양극 발동은 슬롯 목록에 지정된 쪽에서만 일어난다.

[문단 60] 6. 선택지 구성과 극단 행동

[문단 61] 일반 사건은 기본 선택 2개, 극단 발동 사건은 기본 선택을 잠금 표시하고 해당 극단 실행 방식 2개로 교체한다. 잠금 이유는 ‘현재 안정 성향으로 위험한 재진입을 생각하기 어렵습니다’처럼 표시한다. 동료 대안이 개방되면 활성 선택은 최대 3개다.

[문단 62] 극단 실행 방식 하나는 무조건 실행 가능해야 한다. 다른 하나는 물자·무기를 요구할 수 있다. ‘실행 가능’은 ‘생존 보장’이 아니다. 최소 비용은 현재 stamina가 0이어도 실행하고 결과 stamina를 0으로 제한하는 부담 방식이다. 준비형·고강도 선택은 명시 최소 stamina를 충족해야만 실행한다. 이 구분을 requires.stamina와 costs.stamina로 분리한다.

[문단 63] 극단은 목표 고정과 그에 따른 교환을 가진다. 모든 극단에 위험·전리품을 동시에 늘리는 규칙은 두지 않는다. 안정 극단처럼 자산 포기와 손실 회피를 맞바꿀 수 있다. 구체적 효과를 선택 전에 표시하며 “도시의 좀비 전멸” 같은 과장된 결과는 쓰지 않는다.

[문단 64] 7. 판정 규칙과 적용 순서

[문단 65] 7.1 수식

[문단 66] 위험 선택만 난수를 사용한다. 최종 확률 P = clamp(base + trait + condition + equipment + support + flag, 5, 95). 단위는 모두 %p다.

[문단 67] 성향 적합도: 왼쪽 성향이면 (50-x)/50, 오른쪽이면 (x-50)/50. 선택별 가중치 합이 1이 되도록 최대 2개 성향을 지정한다. trait=round(15 × 적합도의 가중합). round는 0.5를 절댓값이 커지는 쪽으로 반올림한다.

[문단 68] condition = 정신력 20 미만이면 -10, 20 이상 40 미만이면 -5, 그 외 0; 여기에 physical=true인 선택만 stamina 20 미만 -10, 20 이상 40 미만 -5와 injury×-5를 합산한다. mental/physical 보정은 선택 전 상태다.

[문단 69] equipment = weaponBonus=true이고 weapon=true면 +10, 그 외 0. support는 협력 동료 +10, 미협력 0이다. flag는 E07에서 access=true일 때 +5, 그 외 0이다.

[문단 70] 일반 위험 base=70, 극단 즉시형=60, 극단 준비형=75다. 확정 선택은 난수를 소비하지 않는다. E12는 확률 공식이 아닌 명시된 경로 조건을 사용한다. 기본 비용이 선택 이후에만 발생해 우열 판단을 왜곡하지 않는지 검수한다.

[문단 71] 7.2 원자적 처리 순서

[문단 72] 1. 표시할 때 현재 상태와 동료 의견을 계산해 미리보기 스냅샷을 만든다.

[문단 73] 2. 선택 시 저장된 사건 ID와 action ID, 필수 자원을 재검증한다.

[문단 74] 3. 동료 참여·독자 행동을 확정한다. 현재 trust를 사용한다.

[문단 75] 4. 비용 차감 전 스냅샷으로 P를 계산한다. 난수 r∈[0,1), 100r<P이면 성공이다.

[문단 76] 5. 기본 비용 + 성공/실패 효과 + 동료 독자 행동 효과를 합해 적용한다.

[문단 77] 6. 성향 변화, 사건 기록, 신뢰도 변화를 적용하고 모든 범위를 제한한다.

[문단 78] 7. injury>=3이면 탈출 실패. 아니면 E12 결과를 결말로 전환하거나 다음 사건으로 진행한다. E12 성공과 치명 부상이 동시에 생기면 탈출 실패가 우선한다.

[문단 79] 8. 결과 기록과 다음 상태를 함께 저장한다. 결과 창 확인은 상태를 다시 계산하지 않는다.

[문단 80] 일반 위험 선택의 초기 손실 템플릿: 비용 stamina -10; 성공 추가 손실 없음; 실패 mental -10, injury +1. 극단 즉시형: 비용 stamina -15; 성공 mental -5; 실패 mental -15, injury +1. 극단 준비형: supply 1 또는 medkit 1을 사건별 지정해 소모, stamina -10; 성공 추가 손실 없음; 실패 mental -10, injury +1. 성공 보상은 슬롯 정의에 따른다. E12 실패는 부상과 무관하게 탈출 실패다. 집필자는 템플릿 변경 시 변경값을 데이터에 명시한다.

[문단 81] 8. 동료 의견·개입·거부

[문단 82] 8.1 의견 선택 우선순위

[문단 83] 각 사건의 동료 의견은 극단 후보 → 구조 주제의 일관된 판단 기록 → 현재 동료 성향 방향 → 실행 가능한 기본 후보 순으로 1개 선정한다. judgmentCounts는 E02/E09/E10에서 구조 목표와 자기 보존 목표를 의도해 선택한 횟수다. 표본>=2, 두 방향 차이>=2일 때만 기록 경향을 적용한다. 그 외에는 성향을 사용한다. null은 집계하지 않는다. 극단 우선은 유지하며 한 번의 구조/거절로 인격 전체를 단정하지 않는다. 기록 우선 적용 사건은 E02/E09/E10이다. 동료와 주인공 성향은 평균내지 않는다.

[문단 84] 의견 표시 자체는 trust와 무관하다. 기존 선택과 action ID가 같으면 선택지를 추가하지 않고 말풍선·동료 추천 배지를 붙인다. 다르면 최대 1개의 대안을 추가한다. 동료만 제안할 수 있는 행동은 requiresCompanion=true로 표시한다.

[문단 85] 8.2 협력과 극단 탈출

[문단 86] 플레이어가 동료 추천과 같은 행동을 선택하면 trust와 무관하게 협력한다. 다른 행동을 선택하면 trust>=40에서 협력, trust<40이면 거부하고 support=0이다. 거부만으로 신뢰도는 추가 감소하지 않는다.

[문단 87] 플레이어의 극단 목표를 벗어나는 동료 대안은 trust>=40일 때만 활성화한다. 낮으면 의견은 보이지만 ‘당신을 제지할 만큼 신뢰가 쌓이지 않았습니다’로 잠근다. 플레이어 목표 고정 안의 두 실행 방식은 동료 추천에 의존하지 않는다. 동료 추천과 다른 실행 방식도 trust>=40이면 협력한다.

[문단 88] 8.3 독자 행동

[문단 89] trust<=30이며 동료 극단이 해당 슬롯에 발동하고, 주인공이 동료 추천과 다른 목표를 선택했을 때만 발생한다. 한 회차 최대 1회다. 실행 방식만 다른 것은 다른 목표가 아니다. 효과는 동료 지원 0과 주인공 mental -10이며 추가 부상·난수·별도 전투는 없다. ‘혼자 돌진해 시선을 끌었다’ 등 사건별 문구를 출력한다. 동료 상태 시뮬레이션 없이 일탈을 체감하게 하는 축소 규칙이다. 조건 충족 시 선택 전 경고를 표시한다.

[문단 90] 8.4 신뢰 변화

[문단 91] 매 사건 trust 변화는 합산 후 -10~+10으로 제한한다. 일반 성공·실패·선호 일치/불일치는 0이다. companionProtected=+8, sharedGoalAchieved=+4, explicitBetrayal=-10만 실제 콘텐츠에 사용한다. E05/E09/E10에 보호 약속 입력을 제공하되, 약속 후 위험 파견 시에만 -10을 표시·적용한다. 약속하지 않거나 주인공이 직접 위험을 감수하면 하락하지 않는다. 보호 약속으로 받을 긍정 보상은 없으며 거짓 약속을 하도록 유도하지 않는다. 낮은 신뢰 도달은 필수 체험·성공 목표가 아니다. 파견에 주인공과 동일한 부상을 전가해 동료가 불사신처럼 보이는 위험은 명시된 공동 수습 장면으로 설명하고, 납득되지 않으면 실행 주체 옵션을 출시 차단 결함으로 본다. E04/E11 양보로 회복한다. 무작위 실패 자체를 배신으로 취급하지 않는다.

[문단 92] 9. 회복과 물자 사용

[문단 93] 아이템 메뉴에서 임의 사용하지 않는다. E04/E11만 회복 창구다. 정비 선택은 supply>=1이면 1을 쓰고 stamina +25, mental +15; supply=0이면 소모 없이 stamina +10, mental +5다. 정비에서 medkit>=1이고 injury>=1이면 치료 확인 옵션을 함께 제공해 medkit 1로 injury -1을 추가한다. 이는 사건 선택과 함께 한 번만 처리한다.

[문단 94] 동료 양보는 supply>=1이고 companion=present일 때만 가능하다. supply -1, trust +10, stamina +10, mental +5, 치료 불가. 단독 대체인 추가 휴식은 stamina +15, mental +10으로 고정한다. 물자 없는 동행 상태에서도 정비는 항상 가능하다. 모든 회복은 해당 슬롯 한 번뿐이며 되돌아가서 반복하지 못한다.

[문단 95] 10. 회차 계승과 서사 규칙

[문단 96] 결말이 표시되는 즉시 현재 주인공의 name, 최종 성향 3축, rescue/self 또는 미발생, ending, 대표 선택 최대 3개를 legacy에 저장한다. 대표 선택은 E02·E07·E10의 action ID다. 미도달 슬롯은 null이며 미발생을 거절로 해석하지 않는다. 새 계승 인물은 다음 회차에 직전 계승 인물을 대체한다. 플레이어가 새 회차 시작을 누르기 전까지 현재 결말과 기록을 유지한다.

[문단 97] 새 회차의 주인공은 설문·생존 수치를 초기화한다. 동료 성향은 직전 회차 최종값을 유지하고 trust=50으로 시작해 이번 회차 동안 고정한다. judgmentCounts와 대표 행동은 의견 선정 및 플레이어 기록에만 쓴다. 이전 물자·부상·신뢰·죽음의 경험은 계승하지 않는다. ending은 시스템·플레이어 회고 화면 전용이다. 결과 화면의 “이번 이야기를 마친다”로 종료할 수 있으며, 다음 회차는 선택 사항이다. 현재 1회차가 동료 없는 구조임을 시작 전에 알린다.

[문단 98] 사망을 포함한 모든 정상 결말은 계승한다. 중도 종료·브라우저 닫기는 계승하지 않고 이어하기로 복귀한다. 치명 부상으로 E02 전에 끝나 기록이 없더라도 성향과 결말은 계승한다. 설정 초기화는 사용자 확인 후 실행하며 진행·계승 기록을 모두 지운다.

[문단 99] 2회차 E02 및 E09/E10에서 현재 동료의 의견과 기여를 제시한다. 개인의 과거 생 기억처럼 말하지 않는다. 연결 근거는 플레이어 기록에서 확인할 수 있다. E09/E10에 추천 목표를 수락하고 협력하면 구조 성공 시 mental +5, 자기 보존 실행 시 기본 stamina 비용 5 감소(최소 0)를 각 사건 한 번 적용한다. 다른 목표를 택하면 이 부가 효과는 없고 일반 협력 규칙만 적용한다. 기여를 결과 문장으로 명시한다. 단, 대사와 정서적 반응도 독립된 가치이므로 모든 의견에 수치 보너스를 붙일 필요는 없다.

[문단 100] 11. UI와 정보 공개

[문단 101] 화면에는 상황, 동료 의견, 선택지, 상태 요약, 최근 결과를 표시한다. 선택은 누르면 즉시 확정하지 않고 의도·대상·비용·알려진 위험·동료 참여를 펼쳐 보여 준 뒤 “실행”으로 확정한다. 그 전 취소는 자유다. 확률·잠금 이유·성향 방향을 공개하되 미발견 결과는 누설하지 않는다. 번역·축약 문구가 실제 행동과 달라지면 출시 차단 결함이다. 자원 요구·확률 미리보기와 실행은 동일 함수·동일 스냅샷을 사용한다.

[문단 102] 확률 미리보기와 실제 판정은 같은 계산 함수를 사용한다. 결과는 선택 의도 → 성공/실패 → 상태 증감 → 신뢰 변화 이유 → 이후 영향 순으로 표시한다. 색상만으로 잠금·위험을 구분하지 않고 텍스트를 함께 사용한다. 키보드 탐색과 모바일 폭을 지원하되 별도 모바일 앱은 만들지 않는다.

[문단 103] 12. 데이터·저장·구현 계약

[문단 104] 권장 구조는 TypeScript 기반 단일 웹 앱, JSON 사건 데이터, 브라우저 로컬 저장이다. 특정 UI 프레임워크는 필수가 아니다. 실행 중 외부 AI 호출과 서버는 필요 없다. 저장소 초기화·기기 변경·시크릿 모드에서 보존을 보장하지 않는다는 안내를 둔다.

[문단 105] 12.1 최소 데이터 모델

[문단 106] RunState: schemaVersion=3, rulesVersion=1.2, runId, eventId, phase(choice/result/ending), protagonist, inventory, flags{access,data,rescueDecision,helpEstablished,routeKnown}, companion{legacy,trust,independentUsed}|null, protectionPromise, rngState, history, lastResult. Profile에는 readTextKeys와 직전 설문 응답을 저장한다.

[문단 107] Legacy: legacyId, sourceRunId, name, traits, rescueDecision|null, judgmentCounts{rescue,self}, representativeActions{E02,E07,E10}, ending. ending은 동료 기억 입력에서 제외한다.

[문단 108] Event: id, dominanceAxis|null, triggerPole|null, baseActions[2], extremeActions[2], companionCandidates, nextEventId, contextVariants.

[문단 109] Action: id, goalId, label, requires, costs, check{base,traitWeights,physical,weaponBonus}|null, successEffects, failureEffects, traitDelta, trustTags, resultTextIds, consequenceType, payOffEventIds. UI 프로필의 접기 키는 textId+contentRevision+contextVariantId이며 플레이 상태와 분리한다.

[문단 110] HistoryEntry: eventId, actionId, preStateSummary, p|null, roll|null, outcome, delta, nextEventId.

[문단 111] 임의 코드를 JSON에 넣지 않는다. requires는 자원 최소값·부상 최대값·플래그 일치·동료 유무를 지원한다. effects는 수치 덧셈·범위 제한·불리언/기록 설정·전량 자원 제거만 지원한다. goalId로 실행 방식과 목표 차이를 구분한다. 데이터 검증기는 누락 ID·가중치 합·이동 연결·맥락별 행동 없음·설명과 효과 불일치를 검사한다.

[문단 112] 12.2 재현과 저장

[문단 113] 회차 시작 seed를 저장하고 xorshift32 등 고정 PRNG 1종을 사용한다. seed=0은 고정된 비영 값으로 치환한다. 난수는 확률 판정당 1회만 소비하며 UI·대사는 소비하지 않는다. 같은 상태·선택·seed는 항상 같은 결과다. 선택 처리 후 결과·다음 상태·PRNG 상태를 하나의 저장 객체로 직렬화해 단일 키에 기록한다. 중복 클릭은 phase와 eventId로 차단한다. 결과 화면 새로고침은 재판정하지 않는다.

[문단 114] 결말 반영과 legacy 교체도 같은 저장 객체에서 수행하고 sourceRunId로 중복 생성을 막는다. 저장 실패 시 오류를 띄우고 진행을 멈추며 마지막 정상 상태를 보존한다. 잘못된 버전·손상된 저장은 무단 초기화하지 않고 재시작 확인을 받는다. 개발 중 v1 이전 저장 호환은 보장하지 않는다.

[문단 131] 14. 개발 순서와 착수 조건

[문단 132] 1단계 엔진: 상태 모델·판정 순수 함수·효과 처리·저장·검증기. 문장 없이 E01→E12를 더미 데이터로 통과시킨다.

[문단 133] 2단계 수직 슬라이스: E04 회복, E05 극단, E12 결말, 계승 후 E05 재진입을 테스트 하네스로 연결한다. 테스트 연결은 제품의 사건 순서를 바꾸지 않는다. 극단·동료·신뢰·계승을 먼저 확인한다.

[문단 134] 3단계 콘텐츠: 12슬롯의 맥락별 선택·결과, 관계 반응, 플레이어 회고 근거를 작성한다. 동료가 과거 죽음이나 이전 생을 기억하는 문장은 금지한다.

[문단 135] 4단계 검수: 위 인수 테스트, 접근성·저장 복구, 조건별 시뮬레이션과 2회차 사용자 테스트를 수행한다.

[문단 136] 단계별 소요 기간은 담당자·경험·작업 시간을 확인해 산정한다. 현재 정보만으로 완성 날짜를 약속하지 않는다. 개발 착수에 필요한 시스템 결정은 이 문서로 닫으며, 개별 선택의 비용·효과·문구를 채우는 작업은 콘텐츠 제작이다. E01·E02·E03·E09 등 슬롯의 상세 보상은 공통 템플릿에서 시작하고 추가 보상을 넣기 전 검증한다. 모든 action 데이터가 채워지기 전에는 콘텐츠 완성으로 판정하지 않는다.

[문단 137] 15. 실현 가능성 판단과 변경 규칙

[문단 138] 가능: 제한된 상태·고정 사건·표 작성 대사로 선택의 흔적과 계승 동료를 구현하고 재현 가능하게 테스트하는 것.

[문단 139] 이번 범위에서 보장 불가: 임의 행동의 의미를 AI가 정확히 해석하기, 모든 선택 조합을 독립 서사로 쓰기, 과거 인격을 사람처럼 완벽히 재현하기, 모든 성향에 동일한 성공률과 만족도를 보장하기. 따라서 ‘인격 재현’은 저장된 세 축·지정된 판단 기록이 작성된 의견으로 드러나는 범위로 정의한다.

[문단 140] 사용자 검증 목표: 최소 5명의 시범 이용자에게 2회차까지 제공하고, 4명 이상이 ‘이전 선택이 현재 동료의 어떤 말/선택으로 돌아왔는지’를 한 가지 이상 설명하는 것을 첫 통과 목표로 둔다. 이는 통계적 효과 입증이 아니라 다음 제작 단계 진입 기준이다. 극단 제한을 이해하지 못하거나 동료 개입을 수치 조작으로만 느끼면 사건·피드백을 수정한다. 실패율·성향별 사용률을 기록하되 초기 표본만으로 우열을 단정하지 않는다.

[문단 141] 축 추가, 동료 수 증가, 자유 탐험, 생성형 AI 도입은 v1.0 승인 범위 밖이다. 요청 시 먼저 상태 조합과 콘텐츠·테스트 증가량을 산정한다. 밸런스 변경은 숫자 데이터만 수정할 수 있으나 저장 중인 회차에는 적용하지 않고 새 rulesVersion의 다음 회차부터 적용한다.

[문단 158] 16. 통합조사 기반 플레이 경험 재점검

[문단 159] 16.1 근거와 해석의 범위

[문단 160] 근거 문서는 「선택형게임_구조적한계_통합조사.docx」다. 「문제_정의서.pdf」를 이번 재점검의 근거로 대체 사용하지 않는다. 조사 기준일 2026-10-28, 대상 17개 게임·개별 리뷰 20건이며 목적표집이다. 아래 게임 사례는 조사서에 수록된 검증 결과를 인용한 것이며 이번 수정에서 원문 웹페이지를 재검증한 것은 아니다. 핵심 요약(1쪽), 리뷰 U01/U02(4쪽), U08~U11(6쪽), U13~U15(7쪽), 쟁점별 분석(9쪽), 반대 사례 비교(10쪽)를 참고했다. 표의 열 위치·기호가 아니라 본문과 개별 리뷰 서술을 근거로 판단한다.

[문단 161] 16.2 앞선 진단에서 바로잡을 것

[문단 162] 조사는 플래그·수치 저장이 곧 의미 소멸이라는 명제를 지지하지 않는다. 제한적 반영의 불만과 정서적 가치의 반론이 공존한다. P2의 일부 불만은 작품 간 계승에 관한 것으로 같은 게임의 회차 단절과 다르다. Exocolonist·Oxenfree는 연결의 반례다. P3의 콘텐츠 탐색과 반복 마찰은 별개다. P4는 직접 불만 근거가 부족하고 Tides of Tomorrow의 전달 시스템이라는 반대 사례가 있다. 따라서 “모든 선택형 게임은 단절되고 성찰을 못 준다”는 전제 및 본 게임의 효과·최초성 주장은 채택하지 않는다. 계승 동료는 사용자에게 유의미한지 검증할 설계 가설이다.

[문단 163] 16.3 선택이 무의미하다는 느낌: 변화 없음과 보이지 않음을 구분

[문단 164] 조사 U02는 기억 알림 대비 후속 언급의 부족을, U09는 오래전 선택의 지속을, 쟁점 분석은 영향 추적의 어려움과 영향 부재의 차이를 다룬다. 우리 게임에서 병원 우회 후 같은 자료를 얻거나 로그에 숫자만 쌓이면 이 문제가 생길 수 있다. E05→E07, E02→E10→E12 연결은 유지하되 결과 기록을 원인 행동·현재 영향·관련 장면 ID로 연결한다. 알림은 실제 후속 반영이 정의된 결정에만 표시한다. 선택 대장에 consequenceType(mechanical/relationship/expressive)과 payOffEventIds를 기록하며, 정서·관계 반응만 의도한 선택을 거짓으로 장기 경로 변화처럼 광고하지 않는다.

[문단 165] 16.4 숫자만 남고 인물이 사라지는 경험도 막는다

[문단 166] U01은 세계 변화가 작아도 정서적 의미를 긍정하고 U10은 어조와 기계적 차이를 구분한다. 모든 선택에 보상을 추가하는 식으로 해석하지 않는다. E02/E09/E10은 구조 대상의 즉각 반응과 동료의 동의·유보·반대 이유를 한 줄 이상 쓴다. 동일 결말이라도 플레이어가 원한 태도를 표현했는지 별도 평가한다. 구조 성공이 언제나 효율 최적이거나 자기 보존이 도덕적 열등 선택처럼 표현되지 않게 한다. E12 조건 공개는 유지하되 “진엔딩/정답 엔딩” 등 위계를 붙이지 않는다.

[문단 167] 16.5 선택 의도와 실제 실행의 불일치

[문단 168] U08은 번역·선택 실수와 자동저장·재시도 마찰을, U09는 긍정 평가와 함께 모호한 표현 문제를 기술한다. 기존 즉시 자동확정은 이런 실수를 고착할 위험이 있다. 선택 확인 UI를 본문에 통합했다. 위험 파견과 보호 약속은 특히 대상·공동 위험·예상 신뢰 변화가 확정 전에 보여야 한다. 확인 후에는 책임을 유지하고 결과 뒤 무제한 재추첨은 제공하지 않는다. 이는 저장 정책의 절충이며 연구가 단일한 정답을 증명한 것은 아니다.

[문단 169] 16.6 계승이 새 포장으로만 느껴지는 위험

[문단 170] 회차 연결만 있으면 반복 피로가 사라진다고 가정하지 않는다. 동료의 실제 행동 기여·판단 근거 기록·정서적 반응을 함께 제공한다. 이전 회차의 죽음을 기억하는 인물이 아니라 이번 세계의 살아 있는 별개 인물이라는 설명을 유지한다. 연결 방식 이해와 본인의 판단을 닮았다고 느끼는지는 서로 다른 테스트 항목이다. 비슷한 결정 세 번으로 일반 인격을 완벽 재현했다고 주장하지 않는다. 관계가 마음에 들지 않아도 현재 회차를 진행하거나 이번 결말로 끝낼 수 있다.

[문단 171] 16.7 반복의 마찰과 수집 동기를 따로 처리한다

[문단 172] U14는 새 요소를 인정하면서도 느린 이동·스킵 부재 부담을, U15는 다회차 몰입을 보고한다. U13은 결말을 바꾸고 싶지 않은 반응을, U12는 같은 경로의 다른 맥락을 보여준다. 따라서 모두를 반복시키거나 모든 엔딩을 보게 하는 것이 성공 기준은 아니다. 2회차부터 직전 설문 응답을 불러와 수정 가능하게 한다. 읽은 본문 접기 기능을 기본 제공하고, textId+contentRevision+contextVariantId가 모두 같은 문단만 접는다. 새로운 동료 의견·새 결과·비용/확률·선택지는 접지 않는다. 선택 자동실행·성향 자동갱신은 금지하며 접기는 난수를 소비하지 않는다. 처음에는 완전 재생을 기본으로 하고 사용자가 읽은 글 접기를 켜면 이후 기기 프로필에 유지한다. 결말 완료율·필수 도전은 두지 않으며 종료도 정상적 수용으로 평가한다.

[문단 173] 16.8 기존 구조를 따를지의 판단 기준

[문단 174] 고정 슬롯·재수렴·조건 변수는 제작 도구이지 장르 관습이라 채택하는 것이 아니다. 현재는 조건 차이와 동료 개입을 적은 콘텐츠로 검증할 수 있어 유지한다. 반대로 매회 같은 글을 다시 읽기, 모든 선택을 큰 분기처럼 홍보하기, 마지막 선택이 모든 결과를 대체하기는 채택하지 않는다. 난수는 중간 위험의 변주에, 누적 조건은 최종 탈출에 사용한다. 특정 작품처럼 타임라인 기억·거대한 분기 지도·멀티플레이 흔적 전달을 추가하지 않는다. 그러한 장치의 존재가 우리 게임의 체험 적합성을 보장하지 않기 때문이다.

[문단 175] 16.9 재점검 결과의 제작·검수 규칙

[문단 176] ① 원인 비교: 같은 seed/설문에서 E05만 바꾸고 E07 행동/자원 차이를 확인한다. ② 인지 비교: 선택 로그를 보지 않은 사용자가 후속 결과의 원인을 설명하는지 기록하고, 로그 확인 후 개선되는지 분리한다. ③ 의도 일치: 선택 확정 전에 예상 행동을 말하게 하고 실제 결과의 행위·대상과 비교한다. ④ 계승 차이: 성향·일관된 기록이 다른 두 legacy에서 동료 의견·행동·관계 반응을 비교한다. ⑤ 반복 마찰: 읽은 문단 접기 전후 클릭 수·읽기 부담과 새 동료 정보를 놓친 수를 기록한다. ⑥ 종료 수용: 다음 회차를 원치 않는 이유가 만족한 완결인지 반복 피로인지 구분한다. ⑦ 표현 검수: death 결말이 있어도 동료가 죽음/부활을 경험했다고 말하지 않는다. ⑧ 최종 경로: stamina 14/15/29/30, injury 1/2/3, routeKnown 조합을 검사한다. ⑨ 성향 경계 22/78 및 맥락별 최소 실행 선택을 검사한다. ⑩ 접기 전후 상태·난수·결말이 동일해야 한다. 20건의 조사 리뷰로 우리 이용자의 비율·만족도·성찰 효과를 추정하지 않는다.

[문단 177] 16.10 문서 정합성과 변경 범위

[문단 178] 이 절은 근거와 검증 기준을 설명하며, 실행 규칙은 1~15절 및 부록에 통합했다. 중복되는 구버전 확률·현재 판단 대사·계승 규칙을 나중 절의 우선 선언으로 덮어두지 않는다. 구현 시 52개 행동 상한 내에서 맥락별 정의를 확정하고 확인 UI·읽은 글 접기·피드백 집필을 별도 작업으로 잡는다. 상태 정의에는 judgmentCounts/helpEstablished/routeKnown을 반영하고, 프로필에 readTextKeys 및 questionnaireAnswers를 둔다. 저장 형식은 schemaVersion=3, rulesVersion=1.2로 고정한다. 구버전 저장은 시작 전에 호환 여부를 알리고 동의 없이 삭제하지 않는다. 서사적 표현, 기계적 영향, 관계 반응은 각각 독립된 검수 항목이다.

[문단 179] 추가 인수 기준: 선택 확인·읽은 글 접기

[문단 180] 미확정 선택을 취소하면 모든 게임 상태와 rngState는 동일해야 한다. 확정 버튼 연속 입력은 1회만 처리한다. 새 contextVariantId, 새 동료 의견, 새 비용/확률은 읽음 여부와 무관하게 표시한다. 동일 본문만 접고 선택 입력은 그대로 받는다. 선택 대장의 장기 영향 알림은 대응 payOffEventIds가 없으면 빌드 검수에서 경고한다. 설문 불러오기는 사용자가 확인하기 전 RunState를 생성하지 않는다.
