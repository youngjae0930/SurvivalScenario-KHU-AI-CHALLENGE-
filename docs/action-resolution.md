> 2026-10-29 최신 기준: 정신력은 스트레스로 반전(stress=100−mental, 초기30). 현재 UI 계약0.3.0, 규칙1.2-stress-1, 콘텐츠opening-core-stress-1이며 자동 저장·이어하기를 지원한다. 상세는 `persistence.md`와 `ui-integration.md`. 아래 구현 단계 설명의 미연결/미저장 언급은 당시 상태다.

기획안 v1.2 §§6~9·부록 A, 기술 설계 초안 v0.2 §2.4의 확정 수치로 구현했다. 내부 API는 `src/engine/index.ts`다. 이후 실제 E01~E04 세션 UI를 계약0.2.0으로 연결했으며 저장은 아직 없다. 최신 앱/UI 연결은 `ui-integration.md`를 따른다.

## 게임에서 가능해진 것

- 필요한 물자·치료 도구·무기·부상 한도·동료·플래그 조건이 맞지 않으면 선택이 잠기고 이유가 반환된다.
- 최소 스태미나 요구와 행동 부담 비용을 구분한다. 무자원 부담형은 스태미나0에서도 시도할 수 있다. 물자 비용은 성공 보상을 먼저 받아 지불할 수 없다.
- 위험 행동은 선택 전 상태로 성공률을 계산하고 난수1회만 사용한다. 비용·성패 효과·의도한 성향 변화가 한 번의 순변화로 적용된다. 성향 변화는 성패와 무관하다.
- 부상 증가와 회복을 모두 합산한 최종 부상이3이면 ending 단계로 반환한다. 실제 증감만 기록해 상한에 막힌 보상을 허위 증가로 표시하지 않는다.
- E04/E11에서 물자 있는 정비(스태미나+25/스트레스−15), 없는 정비(+10/−5), 단독 추가 휴식(+15/−10), 동료 양보(+10/−5·trust+10)를 처리한다. 정비 중 확인한 치료만 medkit1/부상-1을 적용한다.
- E12 단거리(stamina15·injury≤1), 우회(routeKnown·stamina30·injury≤2)를 검사하고 조건 충족 경로 비용을 소모한다. 모두 불가할 때만 구조 요청으로 실패/대기 결말. 탈출 성공 시 data에 따라 자료와 탈출/탈출로 구분한다. 새 부상·성향 변화·난수는 없다.

## 내부 API

| API | 용도 |
|---|---|
| previewCoreAction(input) | 현재 phase/eventId와 물리 요구를 검증, allowed/reasons와 확률 미리보기 반환 |
| resolveCoreAction(input, rngState) | 비용·공통 성향·선택된 성패 효과를 적용한 다음 상태와 result/ending 단계, 판정 결과 반환 |
| applyStateEffects(state, effects) | 순변화 합산·상한/하한·실제 변화 기록. 선택 가능성 검사를 대신하는 함수가 아님 |
| resolveRecovery(input, rngState) | E04/E11 정비·양보·단독휴식·치료. companionTrust와 실제 trustDelta를 함께 반환 |
| getEscapeOptions(state) | E12 경로별 실행 가능 여부와 잠금 이유. 배열 순서는 동료 추천 정책(D01)이 아님 |
| resolveEscape(input, rngState) | E12/choice에서 고른 경로를 검증하고 세 결말 중 하나 반환 |

CoreActionInput은 state/phase/eventId/action/companionPresent/cooperating을 받는다. 동료 존재와 이미 확정된 협력만 전달하며 동료의 추천·거부·독자행동·파견을 결정하지 않는다. 코어 오류는 앱이 기존 ContractError에 매핑할 사항이다.

CoreAction은 명시 costs(스태미나/물자/치료도구), requires, check 또는null, 공통 traitDelta, successEffects/failureEffects를 가진다. 결과별 effects에 성향을 넣는 것은 거부한다. E02 전용 rescueDecision을 다른 사건에서 덮어쓰는 행동도 거부한다. 최종 전체 JSON 콘텐츠 형식이나 집필용 최종 action ID 목록은 이번에 확정하지 않았다.

허용 효과는 정수 가산, 지정 플래그 설정, E02 구조 기록 설정, 무기 설정, 물자/치료도구 전량 제거뿐이다. 임의 코드 실행은 없으며 알 수 없는 효과·빈 배열 슬롯·같은 필드의 상충 설정을 거부한다. 전량 제거와 동일 자원 증감/소모는 순서를 추측하지 않고 오류로 돌려준다. 물자 하한 미달은0으로 보정해 실행하지 않는다.

## 적용 순서와 후속 책임

원본 입력은 변경하지 않는다. 미리보기에서도 비용·결과 효과의 잘못된 데이터를 검증하고 실행은 같은 확률 계산을 사용한다. 결과/종료 단계에서는 재실행을 거부한다. 회복도 반환된 result 단계를 다음 입력에 적용하면 같은 슬롯에서 반복할 수 없다.

**호출자가 반환 상태/단계를 적용해야 하는 순수 함수다.** 같은 과거 입력을 재호출하면 같은 결과를 다시 계산할 수 있다. 실제 UI의 빠른 중복 클릭, 오래된 snapshotId, 영속 결과 확인, 탭 충돌 차단은 앞으로 앱/저장 계층에서 구현해야 한다. 현재 파일에 이를 보장하는 전역 잠금·저장은 없다.

회복의 companionTrust는 부분 입력/출력이며 최종 CompanionState 저장 스키마를 확정하지 않는다. 기본 공통 신뢰 태그·독자행동 효과는 이번 generic resolver에서 자동 생성하지 않는다. 다음 사건 이동·counts·history·Legacy·실제 ViewModel 변환도 아직 연결하지 않았다. 극단 행동의 접근 제한과 trust에 따른 대안 개방은 추후 사건 구성 계층에서 검사해야 한다. 이 함수의 allowed는 물리 조건/단계만을 뜻한다.

치명 부상 결과는 phase=ending/fatal=true로 반환하지만 결말 기록·계승을 생성하거나 저장하지 않는다. E12 입력이 이미 injury3이면 선택을 재개하지 못하도록 거부한다. 현재 UI를 플레이 가능한 버전으로 완성했다고 해석하지 않는다.
