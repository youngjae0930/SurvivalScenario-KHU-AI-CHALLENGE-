# 성향·자원·확률의 실제 계산 흐름

현재 제품은 화면용 고정 결과를 반환하지 않는다. 설문 응답과 실제 회차 상태를 엔진에 넘기고, JSON에 명시한 행동 조건·비용·성향 변화·성패 효과를 계산한다. UI는 공개 계약으로 받은 선택지·확률·변화만 표시한다.

1. 설문 응답ID를 콘텐츠 매핑으로 변환하고 초기 성향을 계산한다. 초기 생존 수치와 상한 등 공통 규칙은 엔진/설정에 정해져 있다.
2. 회차 시작 때 검증된 콘텐츠와 seed로 경로를 정하고 저장에 고정한다. 현재 기본 팩은 필수 장소 순서를 유지한다. 목적지를 선택해서 경로를 바꾸는 기능은 아직 없다.
3. 현재 장소·성향·플래그 등에 맞는 사건/선택 그룹과 문구를 선택한다. 자원이 부족하면 선택 자체를 지우지 않고 잠금 이유를 표시한다.
4. 미리보기는 같은 상태에서 자원 조건·비용·확률·성공/실패 효과를 계산한다. 자원을 소모하거나 난수를 진행하지 않는다.
5. 실행은 최신 상태와 토큰을 검사하고 같은 계산 함수로 재검증한다. 위험 행동은 저장된 PRNG로 성패를 판정하고 확정 행동은 성패 난수를 소비하지 않는다.
6. 성패 공통 비용·성향 변화와 해당 결과 효과를 합산한 뒤 상하한을 적용한다. 실제 변화·기록·난수 상태를 함께 만든다. 비용보다 적은 체력이어도 허용하는 기본 부담 행동과 최소 체력 조건이 있는 행동을 구분한다.
7. 제품 durable 모드는 다음 상태 저장에 성공한 뒤 결과를 표시한다. 저장 실패 시 같은 후보로 재시도하며 이전 정상 상태를 유지한다. 이어하기는 같은 콘텐츠와 기록을 복원하며 재추첨하지 않는다.

사건별 수치가 자동 생성되는 것은 아니다. 예를 들어 ‘물자1 소모’와 ‘감정 쪽+8’은 집필자가 JSON에 정하는 게임 설계 값이고, 실제 보유량이0/1일 때 잠금·차감, 현재 성향과 상태에 따른 확률, 결과 수치와 상한은 엔진이 계산한다. 초기값·확률 공식·회복/E12 같은 공통 또는 전용 규칙은 TypeScript로 구현되어 있다. 따라서 모든 게임 시스템을 JSON만으로 새로 만들 수 있다고 설명하지 않는다.

실제 연결은 `src/app/catalog-client.ts` → `src/engine/catalog/runtime.ts` → `src/engine/actions.ts`/`probability.ts`/`effects.ts` → `src/storage/catalog-save.ts`다. 콘텐츠는 `src/content/catalog/packs/`, 화면 변환은 `src/app/view-models/catalog.ts`다.

E09 검증에서 같은 help 행동이 affect50이면70%, affect70이면76%, 스트레스81이면66%로 계산됨을 확인했다. 시험용 JSON 팩의 comply 비용과 성향/스트레스 효과를 바꾸면 엔진 수정 없이 실제 결과가 바뀌는 테스트도 통과했다. 이는 테스트 전용 입력이며 기본 게임 수치를 변경한 것이 아니다. 같은 상태·같은 선택·같은 난수 위치에서는 같은 결과를 재현한다.
