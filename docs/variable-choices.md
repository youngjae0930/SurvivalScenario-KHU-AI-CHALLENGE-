# 선택 개수 고정 해제

사용자가4개 고정을 철회했다. 앞으로 장면에 필요한 의미 있는 행동만 작성한다. 같은 효과의 문구 변형으로 칸을 채우지 않는다. 의미가 구분되는 기존 선택을 일괄 삭제하는 규칙도 아니다.

작성/등록 스키마·선택 당시 기록·UI는 가변 개수를 처리한다. 그룹의 기술적 범위는1~20개이며 권장 개수나 최소 두 갈래 보장은 아니다. 빈 그룹·중복ID·누락 결과 문구는 거부한다. 기존 무자원 대안, 비용/잠금 이유, 극단의 본인 반대 목표 제한은 유지한다. 극단 동료 슬롯은 인덱스가 아닌 replaceChoiceId로 지정하며 본인 행동과 동료 슬롯을 남긴다.

신규 팩 catalog-variable-choices-1의 E12는 단거리/우회/구조 요청의3개다. 같은 단거리 규칙을 반복하던 E12.barrier와 전용 결과 문구를 제거했다. 실행 가능 조건과 비용·결말 규칙은 바꾸지 않았다. 상태에 따라 실행 가능한 행동이 하나만 남을 수 있으며 이를 숨기려고 같은 효과의 버튼을 추가하지 않는다. 다른 장면의 선택 정리는 이후 서사 보강에서 개별 판단한다.

직전 팩은 opening-catalog-v19.json에 고정했다. 저장된 팩 자체를 복원하므로 이전 저장은 원래 선택 수를 유지하고, 새 시작/새 계승 회차부터 신규 팩을 적용한다. 기존 회차의 선택을 몰래 삭제하지 않는다. 계약0.8.0·저장 schema6/7/8·기존 runtime 버전 유지.

선택 당시 옵션이4개와 다르면 optionCount를 함께 기록해 누락·중복 검사와 저장 재생을 지원한다. 이 필드가 없는 기존 context-1 기록만 당시의4개 규칙으로 검증한다. 과거 기록을 새 구조로 소급 생성하지 않는다.

검증:1/2/3/5개 표시와 저장 복원·선택 기록 누락 거부·극단의 본인1+동료1·이전 팩4개 보존을 자동 확인했다. 브라우저 무저장 체험에서 E01~E12 이동→세 선택 표시→실제 탈출 결말과 오류0건을 확인했다. [화면](screenshots/variable-choices.png).
