# 가변 장소 수와 분량 검증

2026-10-29 D09 진행. 사용자가 보호 약속을 제외했으므로 선언·위반 감점은 개발하지 않는다. 미사용 준비 타입·스키마·검증을 제거하고 재등록을 거부한다. 명령의 위험 분류와 실제 결과 기반 신뢰는 유지한다.

## 플레이에 적용되는 구조

새 회차는 manifest.routeVersion=stages-1을 사용한다. 전반/중반/후반의 최소·최대 방문량을 데이터로 바꾸며, 각 구간의 선택적 장소를 후보로 넣거나 뺄 수 있다. 필수 장소는 한 번씩 포함하고 연결 태그·선행 방문을 지킨다. 실제 탈출 장소를 고르기 전에 나머지 필수/검증 대상 장소를 방문하며 탈출 뒤 다른 장소를 붙이지 않는다.

현재 제품 콘텐츠는 **12개 장소 모두 필수이고 기존 연결을 유지하므로 여전히 한 경로**다. 이번에 새 장소/이야기를 만들거나 기존 사건을 임의 삭제하지 않았다. 구조 검증용 콘텐츠에서는3~5장소 여정, 장소 추가·파일 제외·비활성화, 서로 다른 길이의 첫 회차/계승 회차를 실행했다. 추가 콘텐츠를 넣으면 엔진·UI의 사건 수 목록을 수정하지 않고 반영된다.

장소 예시:

```json
{
  "id": "bakery", "name": "빵집", "stage": "early",
  "tags": ["road"], "fromTags": ["home", "road"], "after": [],
  "required": false, "weight": 1, "enabled": true
}
```

동일한 장소에 사건·네 선택·기본 결과 문구도 제공해야 한다. enabled=false로 선택적 장소를 제외할 수 있으며, 생략은 활성 상태를 유지한다. 필수 장소를 비활성화하면 등록을 거부한다. 선택적 장소 파일을 삭제하는 경우 이를 직접 참조하는 사건의 locationIds 등 참조도 정리한다. 필수 빌라·연구동과 현재 이야기의 선행 관계는 콘텐츠 작성 시 보존한다.

분량을 줄일 때도 활성 장소마다 가능한 경로가 있어야 한다. 예를 들어 시작 장소 하나만 방문하도록 전반부 maxVisits=1로 바꾼다면 전반부 선택적 장소도 함께 비활성화한다. 활성 수보다 큰 최소 방문량, 필수 수보다 작은 최대 방문량, 없는 강제 방문 대상, 비활성 장소에 의존하는 끊긴 연결은 오류로 안내하며 조용히 보완하지 않는다.
