# 데이터 기반 동료 이탈·재회

## 최신: 결과 기반 신뢰·이별 갈등 일반화 (2026-10-29)

사용자는 신뢰80을 구조 전용이 아닌 이별로 이어지는 갈등의 동행 유지 기준으로 수정했다. 신규 journey-2의 conflicts는 실제 playerGoalId/companionGoalId 조합을 명시하며 단순 의견 차이는 이탈시키지 않는다. 현재 구조 장면을 전환했고 이동/조사 갈등도 같은 엔진으로 검증했다. 행동 전 신뢰80·명령 수락60은 별도다.

신규 trustVersion=outcome-1은 실제 체력·스트레스·부상·자원·정보 손익과 콘텐츠에 명시한 이야기 결과를 동료 성향으로 합산한다. 초기 밸런스는 한 선택당±5·최종0~100, 양보 고정+10을 대체한다. 추천 불일치 자체에는 감점을 붙이지 않으며 이탈 중 평가하지 않는다. 성공/실패별 미리보기·실제 이유·저장 재생·실패 재시도를 연결했다. 새 팩 catalog-companion-outcome-1·동행 runtime catalog-companion-outcome-1·계승 catalog-succession-9, 계약0.7.0·schema6/7/8·단독 runtime3 유지, 이전 팩 fixture v17 고정.

보호 약속은 여전히 미승인이며 선언·위반 효과를 추가하지 않았다. 이번 신뢰 시스템 진행을 막는 질문으로 두지 않는다. 상세 [결과 기반 관계](relationship-outcomes.md). 추정93%, 다음은 D09 가변 분량·두 회차약15분 실측/전체 검증이다. 아래 고정+10·구조 전용 이탈·약속 정책 대기는 과거 단계다.


2026-10-29 D03 첫 연결 완료. 사용자는 사건 번호 고정을 거부하고 유동적인 구성을 요청했으며, 고신뢰 기준은 “80 이상으로 적용”으로 확정했다. 정찰·전투 명령, 보호 약속과 파견 위험은 아직 구현하지 않았다.

## 게임 동작

동료가 구조를 추천한 장면에서 주인공이 자기 보존을 선택하면 신뢰80 미만에서 서로 다른 길로 움직이고 80 이상은 동행한다. 판단 보류를 구조 추천으로 바꾸지 않는다. 실제 표시 의견과 동일하게 이전 동일 상황 판단→극단/회복 의견→일반 추천 순서로 사용한다.

실행 전 경고하고 여정이 계속될 때만 이탈한다. 치명 결과·탈출 결말에서는 후속 이탈을 만들지 않는다. 추가 추첨·피해·자원·성향·신뢰 변화를 만들거나 동료의 구조 성공을 확정하지 않는다. 독자 행동을 주인공의 대표 선택이나 구조 집계로 기록하지 않는다.

부재 중 추천·동료 전용 행동·물자 양보는 없다. 극단도 기존 단독 본인4개로 진행한다. 이후 현재 경로에서 재회 태그와 조건을 충족하는 첫 장소에 도착하면 참여를 복원한다. 장소를 경로에 강제 삽입하거나 미도달 재회를 보장하지 않는다. 회차당1회 제한은 없다.

## JSON 확장

manifest에 autonomyVersion: journey-1을 지정하고 사건에 다음 데이터를 넣는다. 엔진은 사건/장소 번호를 분기하지 않는다.

```json
"autonomy": {
  "conditions": [
    { "kind": "number", "subject": "companion", "stat": "trust", "min": 0, "max": 79 }
  ],
  "playerJudgment": "self",
  "companionJudgment": "rescue",
  "reunion": {
    "locationTags": ["safe-hub"],
    "minVisits": 1,
    "conditions": []
  }
}
```

현재 관리실·차량 대기소에 safe-hub 태그를 추가했다. 새 쉼터에도 태그를 주면 기존 이동 개연성과 현재 경로 안에서 재회 후보가 된다. 발동에는 성향·자원·스토리 사실·방문·구간 조건을 조합한다. 재회는 태그 중 하나와 모든 추가 조건을 충족해야 하며 minVisits는 이탈 후 지난 장소 수다. 복귀할 동료 신원으로 재회 조건을 평가한다. 신규 콘텐츠도 신뢰80 이상 동행이라는 승인 기준을 지킨다.

검증기는 버전 누락, 같은 양쪽 판단, 미정의 재회 태그, 잘못된 조건 참조를 거부한다. 실제 경로에 조건을 충족하는 장소가 없으면 부재가 이어진다. 작성자는 후속 경로를 확인해야 한다. 사건·장소 이름과 태그를 바꾼 통합 테스트에서 엔진 수정 없이 다른 곳에서 재회함을 검증했다.

## 코드와 저장

run.companion은 신원을 보존하고 companionJourney.separation이 현재 부재를 표현한다. engine/catalog/companion-journey.ts가 참여 조회·장소 진입 재회를 맡고 runtime.ts가 실제 의견·조건에 따른 이탈을 처리한다. 선택 그룹·미리보기·실행·추천·문구는 같은 현재 참여 기준을 쓴다. UI는 기존 공개 계약의 경고·결과·안내·부재 표시만 사용한다.

이탈은 실행 결과와, 재회는 장소 이동과 함께 저장한다. 저장 실패는 기존 화면을 유지하고 동일 후보로 재시도한다. 저장 재생으로 신원과 참여 전환을 함께 검증한다.

팩 catalog-companion-journey-1, 동행 catalog-companion-autonomy-1·계승 catalog-succession-7, 단독 runtime3. 계약0.6.0·schema6/7/8 유지. 직전 팩은 fixture v15로 고정했으며 구 저장에 새 동작을 소급하지 않는다. 12장소/12사건/22그룹/88선택 항목/145문구 유지.

D08 증거에는 활성 자율 정책과 기본 추천 행동도 포함한다. 동료 때문에 실제 이탈 조건이 달라진 상황을 같은 상황으로 재사용하지 않는다. 현재 팩의 호환 revision은 자기 revision만 허용한다. 새 회차는 참여 기록을 초기화하고 직전 인물의 실제 판단 기록만 계승한다.
