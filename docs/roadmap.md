## 폴더 구조 결정

현재 최상위 구조는 필요한 책임이 이미 나뉘어 있어 유지한다. 모델별 폴더를 만들거나 검증된 engine을 다시 옮기지 않는다. 아래 하위 파일/폴더는 앞으로 구현할 배치 예시이며 현재 생성 완료 목록이 아니다.

```text
src/
  main.tsx                    # React 실행
  App.tsx                     # 앱 생성과 GameRoot 조립
  app/
    create-game-client.ts     # 명령/구독/최신 상태/미리보기 토큰
    view-models/              # 코어+문구를 UI 계약으로 변환
  ui/
    GameRoot.tsx              # 공개 화면 종류에 따른 표시
    screens/                  # 시작/선택/결과/구간완료/결말/기록
    components/               # 상태판/성향/선택 카드/확인창
    hooks/                    # 클라이언트 구독과 UI 임시 상태
    styles/                   # 색·글꼴·레이아웃·반응형·전환
  contracts/                  # 기존 공개 경계 유지, 필요 시 버전 변경
  domain/                     # 기존 내부 타입/검증, 전체 진행 타입 확장
  engine/                     # 기존 순수 코어 재사용·사건/동료/계승 확장
  storage/                    # 저장·복원·호환, D07 결정 후 구현
  content/
    rules/                    # 사건 수치/행동, 설문 답→축 매핑
    texts/                    # 한국어 설문/상황/선택명/결과/반응
  assets/                     # 번들 이미지 등
  test/                       # 공통 지원; 기능 테스트는 대상 옆
public/                       # 직접 URL로 제공할 자산
docs/                         # 실행 기준·로드맵·메모리·원문 참조
```

UI→contracts→app→engine/storage/content 순서로 연결한다. domain은 내부 타입/검증을 제공한다. UI는 공개 모델을 표시하고 명령을 보내며, 규칙·저장소·raw JSON을 직접 읽지 않는다. app이 내부 데이터와 문구를 조립한다. 같은 개발자가 전부 작업해도 이 경계는 유지한다.

기존 App.css와 템플릿 자산은 첫 화면 구현 때 사용처를 확인해 정리한다. 이번에는 파일을 이동/삭제하거나 빈 구조를 대량 생성하지 않는다. 게임 서버·생성형 AI 호출·새 상태 관리 라이브러리는 현 단계에 필요하지 않다.

## 1. 첫 플레이: E01~E04 화면 연결 — 완료

**플레이 경험:** 이름·6문항 설문 → 출발 → 편의점 선택 → 골목 위험 판정 → 휴식/치료까지 직접 조작한다. 결과를 확인하면 다음 사건으로 넘어가고 E04 뒤에는 ‘이번 구현 구간 완료, 다음 E05’ 화면을 보여 준다.

함께 구현한 항목:

- 실제 GameClient, 구독/화면 변환, 오래된 입력·빠른 중복 클릭 차단, 미리보기 토큰과 취소 처리.
- 시작·선택·결과·구간완료 화면, 상태판·성향 표시·확인창·키보드 조작·작은 화면 레이아웃.
- 실제 한국어 설문6개와 답ID→축/±10 매핑. 기획의 축당2개 규칙 유지.
- E01~E04 상황·선택 의도·성패 결과·도움 반응. 비용·확률·실제 변화를 선택 전후로 공개.
- 회복에서 조건에 맞는 치료 확인, 잘못된 행동과 이전 결과 재확인 차단.

**세션 범위:** 새로고침 후 복원되지 않는 메모리 세션이며 화면에 명시했다. GameClient0.1.0의 영속 전용 보장을0.2.0에서 명시적 persistence 능력과 성공 의미로 확장하고 fixture·문서·테스트를 함께 갱신했다. 구간완료도 공개 계약에 추가해 결말로 재사용하지 않는다. 최종 저장 정책 D07은 결정하지 않았다.

**완료 기준:** 브라우저에서 설문부터 E04 완료까지 플레이. 취소는 수치 불변, 실행 비용/난수1회, 결과 확인 후 다음 사건1회. 위험 성패·치료·좁은 화면·키보드 확인. lint/test/build 통과. 최초경고 확인/저장(D05)은 수치·밴드 표시와 구분하고 아직 구현 완료로 보고하지 않는다.

## 2. 저장·이어하기 — 완료

**플레이 경험:** 중간에 닫거나 새로고침해도 마지막 확정 장면으로 돌아오며, 저장 실패가 생기면 같은 결과로 재시도한다.

사용자가 한 브라우저·한 회차·한 활성 탭·같은 결과 저장 재시도·손상/구버전 원본 보존·진행 중 이어하기만 제공을 승인했다. schemaVersion4의 단독 초반 저장을 구현했다. D05 최초 성향 경고는 이번 단계 제외로 확인했고 관련 필드를 만들지 않았다. 상세는 persistence.md를 따른다.

storage 어댑터·재현 검증 디코더·앱 pending/commit·실패 복구를 구현했다. 손상/호환 불가 데이터를 임의 초기화하지 않는다. 기존 OpeningRun을 검증 없이 저장 스키마로 채택하지 않는다. 결말/Legacy를 함께 저장할 후속 확장 경계를 마련한다.

**완료 기준:** choice/result 각각 재시작 복원, 중복 실행 차단, 저장 실패→동일 pending 재시도, 합의한 충돌/호환 동작 검증. 세션/영속 모드의 화면·성공 의미 일치.

## 3. 첫 회차 완주: E05~E12와 결말 — 진행 중

**플레이 경험:** 건물 탐사·철수·자료 조사·구조 선택을 거쳐 탈출까지 완주한다. 성향 극단에 따라 선택이 달라지고 초반 선택이 후반 경로에 영향을 준다.

E05/E06의 규칙·문구·화면·저장·극단 선택과 조기 치명 부상/Legacy 원자 저장을 완료했다. 기존schema4 저장도 보존하며 E04 경계에서 명시적으로 병원에 연결한다. 다음 E07 콘텐츠 확정 전 D04를 확인하고 누락된 효과를 자동 보완하지 않는다. 이후 E08~E10 선택, E11 마지막 회복, E12 조건 공개/세 결말을 연결한다. E05→E07 접근과 E02→E10 연락망→E12 우회가 실제로 이어져야 한다.

정상 결말(치명 부상 포함)은 최종 상태·판단 counts·실제 대표 행동·결말과 Legacy를 같은 커밋으로 보존한다. 미도달 사건은 null이며 거절이나 가상 기록을 만들지 않는다. 여기서는 첫 회차 완주와 계승 기록 생성까지 완료하고, 다음 단계에서 그 기록을 동료로 사용한다.

**완료 기준:** 실제 순서대로12사건 완주, 저자원 대체 행동, 지정 극단 제한/해제, 접근/연락망/우회 인과관계, 치명 부상 우선 종료, 탈출 세 결말과 결말/Legacy 원자 저장 검증.

## 4. 두 번째 회차: 동료·신뢰·계승

**플레이 경험:** 직전 주인공의 성향과 선택 경향을 가진 새 동료가 의견을 내고, 협력·거부·독자행동이 다음 플레이에 영향을 준다. 과거 생의 기억을 가진 인물로 묘사하지 않는다.

동료 판단/행동 후보 전에 D01·D02, 보호 약속/파견 전에 D03을 확인한다. 대표 행동을 판단에 추가 사용하거나 과거 상세 기록을 확장하기 전 D08을 확인한다. 확정 규칙의 신뢰 변화·추천 수락 기여·회복과 이유 문구를 구현한다. 과거 물자·부상·신뢰는 물려주지 않는다.

**완료 기준:** 다른 실제 Legacy가 만드는 의견/협력 차이, trust 경계, 독자행동1회 제한, 승인된 약속/파견 피해·태그, 미도달 null 처리, 두 회차 저장/복원과 새 계승 교체 검증.

## 5. 프로토타입 마감·플레이 검증

**플레이 경험:** 기록을 통해 ‘어떤 선택이 지금 상황에 영향을 줬는지’ 이해하고 두 회차를 안정적으로 끝낸다.

각 단계에서 만든 디자인·스토리를 이어 다듬고 기록/회고·본문 접기·모바일·접근성·오류 안내를 마감한다. 추가 종료 비교/인지 질문 UI 전 D06을 확인하고 별도 회차 시간 목표가 필요할 때만 D09를 확인한다. 문구가 정답 선택/진엔딩 위계를 강요하거나 실제 없는 장기 효과를 약속하지 않는지 점검한다.

**완료 기준:** 첫 회차부터 계승 후 두 번째 회차까지 브라우저 인수 검증, 저장 오류/복원, 비용/확률과 결과 일치, 읽기·선택·초점 접근성, lint/test/build. 최소5명 중4명이 한 인과 사례를 설명하는 기존 관찰 목표는 실제 사용자 검증 때 측정하고 자동 테스트로 달성했다고 보고하지 않는다.
