# 보호 약속 준비 — 제외된 과거 기록

2026-10-29 사용자 “보호 약속은 제외해” 지시로 기능을 제외하고 준비 코드/스키마를 제거했다. 아래 제안은 채택하지 않으며 답변 대기나 다음 구현 항목이 아니다. 실제 신뢰는 [결과 기반 관계](relationship-outcomes.md)를 따른다.

후속 사용자 지시로 [결과 기반 신뢰](relationship-outcomes.md)를 먼저 구현했다. 이 문서의 약속 선언/철회·별도 위반−10 제안은 여전히 미승인이고 새 신뢰 시스템을 막는 결정이 아니다.

2026-10-29: 콘텐츠 형식·검증 구현, 실제 선언/저장/위반 신뢰 변화는 사용자 정책 답변 대기다. 제품 팩·저장·계약0.7.0은 유지하며 진척도91%도 유지한다.

## 작성 형식

초안 manifest.relationshipVersion=promise-1과 event.protectionPromise의 text/conditions를 사용한다. 약속 장면의 모든 파견 행동은 execution.risk에 routine 또는 hazardous를 명시해야 한다. physical·성공률·사건 번호로 위험 파견을 추정하지 않는다. 구 팩의 누락된 risk는 미정이며 안전으로 자동 보완하지 않는다.

약속은 명령 버전이 있는 장면에만 지정할 수 있고, 실제 위험 파견 후보가 하나 이상 필요하다. 위험 분류 누락·위험 행동 없음·관계/명령 버전 누락·탈출 지정·잘못된 조건 참조를 검증기가 거부한다. 아직 이 메타데이터만으로 제품의 보호 약속 기능이 활성화되지는 않는다.

## 답변 대기 정책

사용자에게 다음 기준을 제안했다. 아직 승인으로 기록하지 않는다.

- 해당 사건에서 한 번 선언해 즉시 저장하며 사건 동안 철회하지 않는다. 다음 사건에서 활성 약속은 해제한다.
- 약속 후 명시적 위험 행동을 동료에게 맡기면 성패와 무관하게 신뢰−10이다.
- 약속 자체·직접 실행·약속 없는 파견·일반 실패에는 새 신뢰 변화를 만들지 않는다.
- 보호/공동 목표 보상+8/+4는 구체 행동 매핑 확정 전까지 추가하지 않는다.

근거: AGENTS.md의 미확정 정책 임의 확정 금지와 기술 설계 v0.2 §2.6.2의 약속 확정·철회 시점 미정. 명령 수락60·독자 이탈 방지80은 기존 승인을 유지한다.

## 연결 설계

선언을 행동과 별도 커밋으로 모델링해 난수·물자·성향을 소비하지 않는다. 선언 이력은 선택 이력과 구분하고 저장 재생에서 커밋 순서를 검증한다. 실패 시 기존 화면을 유지하고 동일 선언 후보로 재시도한다. 약속을 새 회차에 활성 상태로 복사하지 않는다.

파견 수락과 비용·성패는 선택 전 신뢰로 확정한다. 위반 신뢰 변화 때문에 같은 행동의 수락을 소급 취소하지 않는다. 미리보기와 실제 결과가 같은 판정 함수를 사용하고 실제 상한/하한 적용 변화와 이유를 표시한다. 네 선택을 유지하며 별도 약속 안내·확인 UI를 사용한다.
