# 실제 다음 회차 시작 (2026-10-29)

> 최신 동료 선택은 [companion-choices.md](companion-choices.md)를 따른다. 이 문서의 신뢰40 규칙/계승 runtime1은 이전 저장 호환 기록이다.

사용자 ‘다음으로 넘어가자’에 따라 결말에서 새 설문을 거쳐 계승 동료와 다음 회차를 시작하는 제품 흐름을 연결했다. 단독 첫 회차와 동행 다음 회차를 모두 E12까지 완주할 수 있다. 일반 추천·협력 보너스·신뢰 변화 전체가 완성되었다는 뜻은 아니다.

## 화면과 진행

1. catalog 회차의 결말에서 **새 주인공과 다음 회차 시작**을 선택한다.
2. 직전 결말과 계승 내역을 확인하고 새 이름·여섯 응답을 입력한다. 이때 저장과 난수는 변경하지 않는다. 취소하거나 새로고침하면 이전 결말로 돌아온다.
3. 출발 확인창에서 계승 범위와 새 여정으로 이어할 것을 안내한다. 확인 후 새 ID·seed와 새 주인공을 생성한다.
4. 새 저장에 성공한 뒤에만 E01을 표시한다. 저장 실패 시 기존 결말 저장은 유지하고 동일 ID·seed·후보로 재시도한다. 실패 화면에서 다시 설문을 제출해 재추첨하지 않는다.

새 주인공은 설문 성향·체력 70·스트레스 30·부상 0·물자 1·치료 도구 1·무기 없음·초기 플래그로 시작한다. 현재 회차의 판단 집계와 선택 이력도 비운다. 동료는 직전 인물의 최종 성향·판단 집계와 신뢰 50을 입력받는다. 과거 물자·부상·신뢰·죽음의 경험은 전달하지 않는다. 별개의 살아 있는 인물이라는 안내를 유지한다.

이전 안정 성향을 가진 동료와 새 모험 주인공을 조합하면, 새 주인공이 E05 모험 극단에 도달했을 때 동료의 우회 대안이 열린다. 일반 행동 비용·성향 변화와 총 네 선택은 기존 제지 규칙 그대로다.

## 계약과 저장

공개 계약은 **0.6.0**이다. `prepare-next-run`은 현재 결말의 sourceRunId/sourceResultId를 확인해 설문을 열고, `cancel-next-run`은 결말로 돌아간다. `start-next-run`은 같은 결말 핸들과 새 설문을 확인해 출발을 확정한다. StartViewModel의 선택적 succession에는 결말 제목과 계승 요약만 전달한다. UI가 Legacy나 동료를 직접 만들지 않는다. fixture와 계약 테스트도 갱신했다.

계승 회차는 **schema8/catalog-companion/catalog-succession-1**이다. 기존 schema6 단독·schema7 개발 동행 저장은 그대로 읽는다. schema4/5는 원래 엔진으로 지원하며 이번 회차 전환을 추가하지 않았다. 저장된 이전 팩에 새 콘텐츠를 삽입하지 않는다. 종료된 catalog 회차에서 사용자가 새 출발을 확정할 때만 최신 팩으로 시작한다.

schema8에는 현재 회차의 전체 팩·초기 입력·진행과 **직전 한 인물의 compact Legacy**를 고정한다. 직전 결말·성향·판단 집계·E02/E07/E10 대표 행동 ID를 보존하지만 이전 회차 전체를 되돌아가 플레이하는 아카이브는 만들지 않는다. 세 번째 회차는 두 번째 인물만 새 동료로 삼고 첫 번째 인물의 기록을 재귀적으로 복사하지 않는다. 진행 중인 동료 입력은 현재 회차가 끝나도 바뀌지 않는다.

복원은 직전 기록의 필드·범위를 검증하고 그 입력으로 초기 동료를 다시 만든 뒤 현재 회차 명령을 재실행한다. 동료와 출처의 불일치·현재 진행 변조는 전체 대조에서 거부한다. sourceRunId는 현재 인물과 달라야 하며, 신규 후보와 기존 회차의 콘텐츠 팩을 별도로 유지한다. 한 슬롯·한 활성 탭·비교 후 쓰기·동일 pending 재시도 원칙을 유지했다.

이 회차 전환은 이번 사용자 요청과 기획 v1.2 문단 96~97에 따른 구현 검토 결과다. D07을 진행 중 재시작이나 미완료 저장 덮어쓰기 허용으로 확대하지 않았다. 현재 회차 종료와 명시적 새 설문 확인을 모두 요구한다.

## 검증

**32파일·385테스트**, lint·TypeScript/Vite build 통과. 추가 7테스트는 설문/취소/재접속 시 저장 불변, 초기 상태·이전 동료 입력 분리, schema8 복원, 저장 실패 동일 후보, 실제 E05 제지의 원인과 복원, 동행 완주와 세 번째 계승의 비재귀성, 중복/오래된 요청/진행 중 덮어쓰기 거부, 이전 고정 팩에서 명시적 출발을 검증한다.

실제 브라우저의 별도 테스트 출처 5180에서 기존 자료 탈출 결말을 이어했다. 준비 취소→재진입→새 설문→신뢰 50 동료와 E01 시작→E05 모험 22에서 우회 제안→새로고침/이어하기 후 동일 선택 복원을 확인했다. 이어 우회 대안을 실행하고 E12 일반 탈출까지 완주했다(마지막 체력 60→45). 현재 인물의 최종 성향 38/42/26·대표 행동과 다시 다음 회차를 시작할 버튼을 확인했다. 콘솔 error/warn 없음.

증거는 `screenshots/succession-e05-resumed.png`, `succession-ending.png`다. 5180 테스트 저장은 새 동행 결말로 갱신해 보존했으며 기존 5173~5179 저장은 변경하지 않았다. 브라우저의 실제 쓰기 실패·모든 성향 조합·모바일 검증을 수행했다고 보고하지 않는다.

전체 프로토타입 추정 **약 95%**다. 다음은 동료의 일반 추천·협력/거부·신뢰 변화·회복 양보 연결이다. 미정인 D01 순위와 D03 보호 약속/파견, D06 추가 회고 질문을 이번에 확정하지 않았다. 목적지 선택 이동과 랜덤 콘텐츠 대량 확장은 프로토타입 마감 뒤에 진행한다.
