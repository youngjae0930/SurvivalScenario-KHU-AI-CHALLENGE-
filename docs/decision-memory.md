# 선택 당시 상황 보존 — 생존 시나리오: 봉쇄 도시

## 이번 단계

D08의 첫 단계로 실제 선택 직전 상황을 기록하고 결말의 Legacy를 거쳐 다음 회차에 전달한다. 당시 상황을 보존하는 기반이며, 동일 상황 판정·선택 재현·대표 선택의 약한 선호 가중치는 아직 적용하지 않는다. 화면의 추천·게임 수치·성패·네 선택 구성은 이전 단계와 같다. 새로운 문턱이나 가중치를 확정할 필요가 없는 기록 단계부터 진행했다.

## 기록 내용

새 팩에서 실제로 실행한 각 선택은 `CatalogHistory.decisionContext`에 다음을 남긴다.

- 콘텐츠 팩/버전/규칙, 사건·장소·구간·그룹·장면 문구 ID, 지금까지 방문한 장소.
- 선택 직전 주인공 성향·체력·스트레스·부상, 물자·치료 도구·무기·플래그·스토리 사실.
- 당시 동료 유무·성향·신뢰·판단 집계.
- 화면에 제공된 네 행동의 ID·목표·판단 종류·실행 가능 여부와 이유·미리보기 성공률·실제로 선택된 행동 variant·명시된 속도·탈출 경로.
- 최종 선택 행동은 선택적 치료를 포함한 규칙을 별도로 보존한다. 평상시 미리보기/추천 조회만으로 기록하지 않는다.

E02는 물자가 있으면 물자 양보, 없으면 체력을 쓰는 실제 variant를 구별한다. E04 치료는 치료 전 부상과 치료를 포함한 비용/효과를 기록한다. 양보는 신뢰50→60 이후에도 당시 신뢰50을 유지한다. 극단의 `companion:` 명령과 탈출 경로/잠금도 원문대로 남긴다. 결과나 난수 roll을 선택 이전 정보로 복사하지 않는다. 당시 값과 행동 정의는 별도 복사하므로 이후 상태 변화로 덮어쓰지 않는다.

## 계승과 한도

결말에서 실제 도달한 선택만 `CatalogLegacy.decisionMemory`로 보낸다. 한 회차의 여정 상한인48개(세 구간 각 최대16)까지이며 매 순간 후보는4개다. 회고의 대표 선택 E02/E07/E10 최대3개는 기존 ID 그대로 유지하며, 상황 보존은 전체 실제 선택에 대해 수행한다. 조기 종료에 미도달 사건을 채워 넣지 않는다.

다음 회차는 기존처럼 새 설문·초기 생존값·신뢰50으로 출발한다. 과거의 체력·물자·무기·통로 정보는 현재 상태가 되지 않는다. 상황 자료는 직전 인물의 `previousLegacy`에만 보관하며, 동료가 이전 시간선의 사건을 기억한다는 스토리를 추가하지 않는다. 세 번째 회차에는 두 번째의 실제 선택 기록을 새로 남기고 첫 번째의 Legacy 전체는 재귀 보관하지 않는다. 당시 동료 상태는 실제 판단 입력이므로 그 한 순간의 이름/성향/신뢰를 포함할 수 있지만 과거 여정 전체를 담지 않는다.

## 버전과 호환

신규 팩 `catalog-decision-memory-1`, manifest.decisionMemoryVersion=`context-1`. 이전 추천 팩은 `src/test/opening-catalog-v13.json`으로 고정했다. 계약0.6.0과 schema6/7/8을 유지하며 런타임을 구분한다.

| 회차 | 새 런타임 |
| --- | --- |
| 단독 schema6 | catalog-runtime-3 |
| 동행 schema7 | catalog-companion-memory-1 |
| 실제 계승 schema8 | catalog-succession-5 |

구 팩은 기존 런타임과 저장 원문을 유지하며 상황을 소급 생성하지 않는다. 구 결말에서 신규 팩으로 출발하면 직전 Legacy에 상황 기록은 없는 채로 두고, 새 회차에서 하는 선택부터 기록한다. 메타데이터에 알 수 없는 버전을 넣으면 콘텐츠 스키마가 거부한다. 네 선택이 아닌 팩에 상황 기록 버전을 덧붙여 소급 업그레이드할 수도 없다.

현재 회차의 상황은 저장 디코더가 원본 시작 입력과 선택 명령을 재생하여 전체 checkpoint/Legacy와 대조한다. 직전 Legacy는 원본 회차 전체를 재귀 보관하지 않으므로 별도의 원본 재생 증명은 없고, 닫힌 형식/한도/순서/선택 참조/치료 규칙/대표 선택/집계/최종 성향의 일관성을 검증한다. 이 검증을 과거 전체의 진위 증명이라고 설명하지 않는다.

대표 선택 검증에서 실제 동료 명령의 `companion:` 접두사도 허용하도록 수정했다. 기존에는 실제 E07 동료 선택을 기록하고도 계승 검증이 해당 ID를 거부할 수 있었다. 실제 E07 동료 선택→결말→저장 복원→다음 회차를 검증했다.

## 검증

38파일461테스트, lint/build/content:check 통과. 새13개 테스트는 실행 전 상태/후보 복사, 자원별 variant, 치료·양보, 탈출, 직전 기록만 계승, 구 저장 원문 유지, 상황 누락/수치 변경 거부, Legacy 중첩/중복/불일치 거부, 실제 동료 명령 ID, 조기 종료, 이전 팩과 동일 결과·난수 순서, 저장 실패 동일 결과 재시도를 확인한다. JSON Schema5개도 갱신했다. 공개 화면/계약은 변경하지 않아 이번 단계의 검증은 엔진·앱 명령·저장 통합 테스트로 수행했다.
