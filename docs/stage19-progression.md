# 19스테이지 최소 확장 — 2026-10-30

신규 기본 팩은 `stage19 / catalog-stage19-1`이다. 기존12사건 팩 `opening / catalog-dialogue-1`과 모든 과거 저장은 유지한다. 새로 출발하거나 결말에서 다음 회차를 명시적으로 시작할 때19스테이지 팩을 사용한다. 진행 중인 기존 회차에 장소를 끼워 넣지 않는다.

- 고정9슬롯과 A/B 후보10슬롯이다. 전체54장소 정의 중47개가 활성이고 연구동7개는 예약/비활성이다. 한 회차에54곳을 전부 방문하는 방식이 아니다.

- 선택 개수는 장면에 따라 다르다. 경로 선택은2개 또는 일반2개+연구동 잠금1개다.

## 최소 구현의 경계

판정 확률·비용·성향 변화·회복·추천·신뢰·이별/재회·탈출·계승은 기존 규칙을 재사용한다. 일반 이동에는 기존 E03 행동, 휴식에는 E04 회복을 사용한다.1번 출발,4번 배분,11번 구조/신호,18번 위기,19번 탈출도 기존 행동을 연결했다. 빌라 계단의 도움은 기존 E02 행동을 재사용하되 고정 세 주요 판단의 집계에 추가하지 않고, 실제 성향/효과와 개별 선택 기록에 남긴다. 주요 판단 집계는4·11·18번의 최대3회다. 새 장소 번호와 기계적 규칙 E01~E12는 별개다.

경로를 고르는 행동은 이동 목적지만 확정하며 비용·확률·성향 효과를 추가하지 않는다. 선택의 손익 차이와 장소별 전용 행동을 다듬는 작업은 후속 콘텐츠/균형 작업이다. 반복 휴식과 이동 템플릿이 있으므로 이번 작업으로 모든 공간의 고유 기믹이나 목표 플레이 시간을 완성했다고 보지 않는다.

**감염 수치/전염 판정, 히든 개방, 치료제 획득, PDF의 신규5종 엔딩 분류는 미구현이다.** 좀비 연쇄 위기는 기존 위험/부상 행동과 장면으로 표현한다. 지하터널/외곽 검문소 탈출은 서로 다른 장소/문구를 사용하지만 엔진의 기존 `escape` 분류를 공유한다. `data-and-escape`/`escape-failed` 등 과거 분류도 유지하며 치료제 엔딩으로 바꾸지 않는다.

## 슬롯 데이터와 확장

`src/content/catalog/packs/stage19/manifest.json`의 `slotPlan`이 진행 표다. 구간마다 `id`, `stage`, `slots`, `nextSegmentIds`를 정의한다. 슬롯의 `number`는 전체 순번, `candidates`는 그 순번에 배정할 장소ID 목록이다. 한 후보면 고정, 복수 후보면 기존 장소 `weight`로 추첨한다. 이번 후보는 기존 기본값1을 사용하며 회차 간 반드시 다른 곳을 강제하지 않는다.

```json
{
  "id": "hospital",
  "stage": "middle",
  "slots": [
    { "number": 8, "candidates": ["hospital-desk"] },
    { "number": 9, "candidates": ["er-waiting", "hospital-security"] }
  ],
  "nextSegmentIds": ["subway", "school", "research"]
}
```

위 예시는 필드 설명용 발췌이며 실제 병원 구간은8~14번7슬롯을 모두 정의한다.

장소를 추가하려면 다음 데이터를 편집한다. 엔진이나 UI의 장소 목록을 고칠 필요는 없다.

1. `locations/`에 새 장소 JSON을 둔다. 해당 구역, `slot-N` 태그, 이전 슬롯 `slot-(N-1)`의 `fromTags`를 맞춘다. 후보 장소는 `required:false`, 고정 장소는 `required:true`다.
2. 목적 슬롯의 `candidates`에 장소ID를 추가한다. 이번19슬롯의 A/B 편성을 바꾸려는 의도 없이 다른 순번 후보를 섞지 않는다.
3. `events/`에 `locationIds`/`locationTags`, 선택 그룹과 기존 계약에 맞는 행동을 작성한다. `scripts/`에는 장면/결과/동료 의견의 반복 가능한 기본 문구와 필요한 공간·자원·스탯 조건을 둔다. 파일명/추가 import 목록은 필요 없다.
4. 분기는 출발 구간 마지막 슬롯의 선택에 `destinationSegmentId`를 지정하고 해당 구간의 `nextSegmentIds`와 맞춘다. 조건 미정인 경로는 `lockedReason`을 유지한다. 연구동을 열려면 실제 종착/사건과 정책부터 완성해야 검증이 통과한다.
5. 콘텐츠 변경 시 `revision`을 올리고 `decisionEcho.compatibleRevisions`의 의미 호환 여부를 검토한다. 기존 저장은 수정된 파일 대신 저장 당시 팩을 사용한다.

전체 계약은 `src/domain/catalog.ts`, JSON Schema는 `docs/content-schemas/`다. 스크립트 조건/우선순위/대화 작성은 `docs/content-authoring.md`, `docs/dialogue-authoring.md`를 따른다. 장소별 추가 파일도 자동 수집되므로 기존 대형 JSON을 매번 다시 쓸 필요가 없다.

## 추첨과 저장

출발 시 전반부7곳을 배정한다.7번 선택을 실행할 때 해당 중반부7곳을 배정하고,14번 선택 실행 시 후반부5곳을 배정한다. 선택 전 미리보기와 동료 의견 조회는 경로 난수를 소비하지 않는다. 화면의19칸 중 아직 선택하지 않은 구간은 ‘경로 선택 후 결정’으로 표시한다.

경로 선택 결과의 저장 후보에는 추가된 장소와 RNG 상태가 이미 들어 있다. 영속 저장 성공 뒤만 화면을 확정하고, 실패 시 같은 후보를 재시도한다. 새로고침/이어하기는 시작 시드와 실제 행동을 재생해 경로 전체를 대조하므로 방 배정/경로를 바꾼 저장은 거부한다. 저장 크기 한도는 기존2,000,000자를 유지한다.

공개 UI 계약0.8.0과 schema6/7/8을 유지한다. 신규 런타임만 구분한다.
