# 조건부 경로 준비 (2026-10-30)

조건부 경로 준비 후 사용자 기준이 확정돼 `catalog-research-1`에 실제 연구동을 연결했다. **병원의 무작위 여분 장소에서 수송 기록을 조사해야 진입하며 백화점에서는 이동할 수 없다.** 세부 내용과 검증은 [연구동 연결](research-route.md)을 따른다.

`manifest.slotPlan.segments[].entry`는 다른 구간에서 해당 구간으로 들어갈 때 평가할 `conditions`와 실패 안내 `reason`을 지정한다. 기존 상태 조건 문법을 재사용하며 사건 번호나 특정 연구 단서를 엔진에 하드코딩하지 않는다.

```json
"entry": {
  "conditions": [{ "kind": "fact", "id": "research-clue", "value": true }],
  "reason": "연구동으로 이어지는 단서가 필요합니다."
}
```

이는 현재 연구동 진입 조건을 나타내는 작성법 예시다. `lockedReason`은 콘텐츠 예약을 위한 별도 잠금으로, 진입 조건을 충족해도 해제되지 않는다. 시작 구간에는 조건을 지정할 수 없고, 분기마다 예약되지 않은 무조건 후속 경로가 하나 이상 필요하다. 없는 사실/장소를 참조하는 조건은 등록을 거부한다.

선택 미리보기와 실제 실행은 모두 **행동 직전의 동일한 상태**로 조건을 확인한다. 선택의 성공 효과로 단서를 주더라도 그 선택 자체의 진입 조건을 사후 충족시키지 않는다. 잠금 실패는 상태와 난수를 변경하지 않는다. 화면에는 기존 잠금 이유 계약을 그대로 사용한다.

과거 팩에는 entry가 없으므로 이전 규칙을 유지하며 새 조건을 삽입하지 않는다. 실제 연구동은 별도 콘텐츠 revision과 저장 재생 검증으로 연결했다.
