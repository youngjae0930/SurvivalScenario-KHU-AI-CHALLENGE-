# 감염·전염 최소 구현 (2026-10-30)

사용자 확정: **감염은 진행 없이 즉시 사망**, 적용 대상은 **주인공과 동료**다. 물림·감염 혈액의 위험 접촉을 명시한 행동이 실패했을 때만 감염된다. 단순 접촉·일반 부상·공기·시간 경과로 자동 감염시키지 않는다. 일반 치료 도구는 부상을 위한 도구이며 감염을 치료하거나 면역을 주지 않는다.

## 게임에서 달라진 점

- 기존 열차 연결 구간과 외곽 탈출 행렬의 구조 행동만 감염 위험을 추가했다. 장소54개·사건54개·JSON 스크립트1018개는 유지했다. 집단 확산 장면도 기존 문구를 재사용한다.
- 맨손 구조 실패는 실제 실행자가 물린다. 직접 실행하면 주인공, 명령 또는 극단의 독립 동료 선택이면 동료다. 동료에게 구조를 맡기는 기존 수락 기준60은 유지한다.
- 처치 도구를 쓰며 함께 옮기는 구조는 실패하면 실행자가 물리고, 이어 감염된 실행자의 혈액이 다른 동행자의 상처에 닿는 위험을 명시한다. 동료 없이 실행하면 주인공에게만 적용된다. 새 추첨은 없다.
- 선택 설명·확인창에 위험과 대상을 먼저 보여준다. 감염 결과에서는 생존을 전제하는 기존 실패 문구 대신 짧은 접촉·사망 문구를 보여준다.
- 주인공 감염은 `infection-death` 결말로 즉시 종료한다. 감염 기록이 있으면 일반 부상 결말보다 우선한다. 현재 등록 검증은 확정 탈출 행동에 감염을 붙이지 못하게 하므로 마지막 탈출에 숨은 감염 추첨은 없다.
- 동료 감염은 동료 참여를 영구 종료한다. 추천·명령·극단 대안·재회가 중단되며 주인공이 살아 있으면 혼자 진행한다. 상태창에 동료 사망을 남긴다. 계승은 성향·판단만 복사하므로 다음 동료는 살아 있고 감염되지 않은 상태다.
- 모든 그룹에 감염 노출 없는 무자원 대안이 남는다. 전 장소의 좀비 조우를 일괄 감염 판정으로 바꾸지 않았다.

## 콘텐츠 추가 방법

`src/content/catalog/packs/stage19/manifest.json`의 `infectionVersion: "immediate-1"`이 있는 팩만 이 규칙을 사용한다. 실패 가능한 `action` 선택에 다음 메타데이터를 작성한다.

```json
"infection": [
  { "source": "infected-person", "target": "actor", "contact": "bite" },
  { "source": "actor", "target": "other", "contact": "blood" }
]
```

첫 줄만 있으면 물린 실행자만 사망한다. 둘째 줄은 그 실패 안에서 실제 감염된 실행자로부터 다른 동행자에게 혈액이 들어가는 접촉이다. **명시한 순서대로 같은 실패 순간의 접촉을 평가**한다. 즉시 사망 규칙이므로 감염자를 살아 있는 채로 다음 사건까지 데려가지 않는다. 둘째 접촉을 쓸 때는 상황/선택 설명에 공동 접근과 혈액이 상처에 닿는 위험을 설명해야 한다. 멀리 떨어진 동료에게 자동 전염시키거나 이미 사망한 동료를 다음 장소의 전염원으로 취급하지 않는다.

`source`: `infected-person`은 콘텐츠가 확정한 감염자다. `protagonist`/`companion`/`actor`는 실제 감염이 확인되어야 전염원이 된다. `target`: `protagonist`/`companion`/`actor`/`other`. `actor`는 실제 실행자, `other`는 그 반대 인물이다. 같은 대상의 중복 기록, 부재·이탈·기존 사망 동료 대상 접촉은 무시한다. `contact`: `bite`/`blood`만 허용한다. 일반 상처만으로 감염을 추측하지 않는다.

핵심 파일:

- `src/domain/catalog.ts`: 콘텐츠·감염 사망 근거·판단 기록 타입.
- `src/engine/catalog/infection.ts`: 순수 접촉 평가. 난수/시간/저장 접근 없음.
- `src/engine/catalog/runtime.ts`: 미리보기·실행·종료·판단 기록.
- `src/engine/catalog/companion-journey.ts`: 사망 동료의 참여·재회 차단.
- `src/content/texts/infection.ts`: 최소 공통 결과·위험 문구.
- `src/app/view-models/catalog.ts`, `src/ui/components/StatusPanel.tsx`: 상태·위험·결말 표시.

## 저장·계약

신규 팩 `stage19/catalog-infection-1`. 계약 **0.9.0**, `StatusViewModel.infection`은 과거 팩에서는 생략하는 선택 필드이며 `EndingKind`에 `infection-death`를 추가했다. UI는 상태나 전염을 재계산하지 않는다. 샘플은 `snapshotFixtures.infectionEnding`이다.

저장 schema6/7/8을 유지하고 감염 팩만 런타임 **solo7/companion-infection-1/succession13**으로 구분한다. `infectionDeaths`에는 실제 대상·전염원·접촉·장소 순번·사건·선택을 기록한다. 팩과 행동을 재생하여 기록 전체를 비교한다. 저장 실패는 화면/이전 저장을 유지하며 동일 후보를 재시도하므로 감염을 다시 뽑거나 중복 적용하지 않는다.

이전 경로 팩은 `src/test/route-identity-catalog-v1.json`에 고정했다. 과거 저장은 감염 필드를 생성하지 않고 원래 규칙·난수·문구로 이어간다. 새 팩은 **새 출발 또는 명시적 다음 회차**부터 적용된다. 현재 진행 중인 구 저장에는 감염을 삽입하지 않는다. D08 비교에는 새 감염 조건·접촉 메타데이터를 포함하고 호환 revision은 새 팩 안으로 제한한다.
