# 동료에게 행동 맡기기

2026-10-29 구현 완료. 사용자가 명령 제안의 신뢰 기준을 “60으로 하자”로 수정했다. 명령 수락은60, 직접 행동에 따른 독자 이탈 방지는 기존80으로 구분한다.

## 게임 동작

명시적으로 지정한 행동만 확인창에서 직접 실행/동료 선행 실행을 고른다. 현재는 골목 관찰·돌파 정찰과 병원 진입을 연결했다. 전투 등 다른 역할도 콘텐츠의 role·조건·공동 위험 설명으로 추가할 수 있으나 새 전투 사건을 만들지는 않았다. 장면의 네 선택은 유지한다.

동료의 현재 추천 행동과 같으면 신뢰와 무관하게 수락한다. 다른 행동도 신뢰60 이상이면 맡길 수 있다. 낮은 신뢰·부재·조건 불충족은 이유를 표시하고 동료 실행을 막으며 직접 실행으로 자동 전환하지 않는다. 동료가 있어도 미지정 행동·회복·탈출·극단의 별도 동료 슬롯에 일괄 파견을 추가하지 않는다. 숨은 반대 목표도 열지 않는다.

직접/동료 실행의 기존 공용 비용·주인공 상태 기반 성공률·성패·피해·성향·집계는 같다. 협력 보너스·신뢰 변화·동료 체력/부상·별도 난수를 추가하지 않는다. 공동 위험은 확인창과 결과에 표시한다. 기존 명령 수락은 지시를 따르는 판단이며, 주인공이 직접 자기 보존을 택할 때 적용하는 신뢰80 독자 행동과 다르다. 명시적으로 수락한 동료 실행과 독자 이탈을 동시에 발생시키지 않는다.

## 콘텐츠

manifest.executionVersion=command-1과 일반 선택의 execution 메타데이터를 사용한다.

```json
"execution": {
  "role": "정찰",
  "conditions": [],
  "sharedRisk": "동료가 앞서 움직이고 주인공은 이동과 후퇴를 지원한다."
}
```

역할명은 콘텐츠가 정의한다. physical·사건 번호로 파견을 추론하지 않는다. 조건은 기존 성향·자원·사실·장소·구간 조건을 재사용한다. 확정 행동에는 없는 실패 피해를 서술하지 않는다. 실패 부상이 있는 행동에는 주인공의 공동 위험이 드러나는 개별 설명을 넣는다. UI가 새 선택을 만들어내거나 모델이 수치 보너스를 임의 추가하지 않는다.

## 계약·저장·계승

계약0.7.0: PreviewActionRequest.executionActor는 선택 사항이고 미지정은 직접 실행이다. ActionPreviewViewModel.execution의 현재 actor와 두 options/잠금 이유를 UI가 그대로 표시한다. 확인창에서 주체를 바꾸면 새 previewToken을 발급하며 이전 토큰을 실행할 수 없다. commandPreviewFixture가 사용 예시다.

실제 동료 실행은 history.execution에 주체·역할·공동 위험을 기록한다. decisionContext.executionActor와 후보 메타데이터/신뢰60 경계도 보존한다. 같은 상황의 이전 위임은 action 추천과 이유로 이어지고 주체 선택은 플레이어에게 남긴다. 치료·행동·주체를 묶은 동일 후보를 저장하며 실패 시 이전 화면을 유지한다. 저장 재생은 주체와 실제 결과를 함께 검증한다.

팩 catalog-companion-command-1, 동행 catalog-companion-command-1·계승 catalog-succession-8. schema6/7/8과 단독 runtime3 유지. 이전 팩은 fixture v16에 고정했다. 기존 저장에 명령을 소급 적용하지 않으며 구 엔진의 동료 실행 요청도 거부한다. 현재 콘텐츠는12장소/12사건/22그룹/88선택 항목/145문구 유지다.
