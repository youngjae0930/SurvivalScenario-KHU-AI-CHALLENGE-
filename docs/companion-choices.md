# 극단 장면의 동료 선택

2026-10-29 사용자 수정 적용. 기존 신뢰 기반 제지와 구분한다.

## 게임 동작

- E05~E10 극단 장면의 본인 선택은 신뢰와 무관하게 자기 목표 안의 세 방식으로 제한한다.
- 동료가 있을 때 네 번째 칸을 **동료 선택**으로 예약한다. 전체는4개다. 동료가 없으면 원래 본인4개다.
- 동료 성향이 반대 방향이면 기존 일반 그룹의 반대 목표를 동료 선택으로 제공한다. 신뢰0도 가능하다.
- 동료 자신의 지정 극단이 먼저 적용되며 E09/E10은 기존 유효 판단 집계 우선순위를 유지한다.
- 같은 방향·중립50·집계 미성립이면 콘텐츠에서 지정한 기존 네 번째 행동을 동료 선택으로 사용한다. 중립의 일반 추천 순위는 확정하지 않았다.
- 동료 선택은 일반 행동과 같은 비용·판정·성향 변화·성공/실패 효과를 갖는다. 자원 부족이면 이유와 함께 잠근다. 협력 보너스·신뢰 증감·파견·약속 효과는 없다.

예: 모험 극단의 병원 장면에서 본인은 돌입 세 방식만 택한다. 안정 쪽 동료는 병원 우회를, 모험 쪽 동료는 함께 통로를 뚫는 방식을 제공한다. 신뢰100이어도 본인용 일반 우회는 열리지 않는다. 내부 risk축은 낮을수록 모험이며 사용자 예시의 ‘모험100’은 모험의 강도를 뜻한다.

## 콘텐츠와 명령

이벤트 intervention에 선택 필드 mode: companion-choice를 넣는다. groupId는 극단 그룹, replaceChoiceId는 기본 동료 행동과 교체 위치, alternatives는 조건별 반대 행동 참조다. 기존 그룹·행동·문구를 재사용하므로 수치나 이야기를 복제하지 않는다. 조건이 맞는 참조 중 기존 그룹 우선순위를 적용한다. 반대 참조가 없으면 기본 동료 행동을 사용한다. 검증기는 극단 축·동일 목표 본인 그룹·일반 행동 참조·남은 본인 무자원 대안을 검사한다. 모든 작성 그룹은4개다.

런타임 동료 명령 ID는 companion:<원래 행동ID>다. 예: companion:E05.bypass. 콜론은 작성용ID에서 금지되어 충돌하지 않는다. 현재 제공된 동료 명령만 실행할 수 있으며 일반ID로 직접 우회하거나 동료 없이 명령을 보내면 거부한다. 결과 문구는 원래ID로 조회하고 실행/결과/계승에는 실제 동료 명령ID를 기록한다. UI는 기존 계약0.6.0의 requiresCompanion/recommended와 opinion을 그대로 표시한다. 추가 공개 타입은 없다.

## 저장 호환

팩 revision catalog-companion-choice-1. 단독 schema6/runtime2 유지. 동행 schema7은 catalog-companion-choice-1, 계승 schema8은 catalog-succession-2로 구분한다. 구 mode 없는 팩은 신뢰40 규칙을 그대로 실행한다. 구 schema7/intervention1 및 schema8/succession1을 재생/비교 검증한다. 신규 규칙은 진행 중 회차에 삽입하지 않고 다음 회차를 명시적으로 시작할 때 채택한다.

저장 전 화면 확정 금지와 동일 후보 재시도는 유지한다. 신규·구 저장 모두 콘텐츠 전체를 고정한다.

## 검증

33파일403테스트 통과. 여섯 극단 장면의 신뢰0/29/39/40/50/100, 본인 극단0/100, 같은 방향/중립/동료 없음, 판단 집계, 명령 우회 거부, 원래 효과 재사용, 자원 잠금, 저장 재생·실행버전 위조·구 schema7/8·동일 후보 재시도를 확인했다. lint/build 및 content:check 통과. 브라우저에서 신뢰0 우회 실행과 체력80→75·성향22→30, 같은 방향 동료 슬롯을 확인했다.

일반 장면 전체의 동료 추천과 협력·신뢰 변화·양보는 후속 범위다. D01 중립 전체 순위 및 D03은 미정이다.
