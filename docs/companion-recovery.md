# 동료 양보와 정비 추천

## 최신: 결과 기반 신뢰·이별 갈등 일반화 (2026-10-29)

사용자는 신뢰80을 구조 전용이 아닌 이별로 이어지는 갈등의 동행 유지 기준으로 수정했다. 신규 journey-2의 conflicts는 실제 playerGoalId/companionGoalId 조합을 명시하며 단순 의견 차이는 이탈시키지 않는다. 현재 구조 장면을 전환했고 이동/조사 갈등도 같은 엔진으로 검증했다. 행동 전 신뢰80·명령 수락60은 별도다.

신규 trustVersion=outcome-1은 실제 체력·스트레스·부상·자원·정보 손익과 콘텐츠에 명시한 이야기 결과를 동료 성향으로 합산한다. 초기 밸런스는 한 선택당±5·최종0~100, 양보 고정+10을 대체한다. 추천 불일치 자체에는 감점을 붙이지 않으며 이탈 중 평가하지 않는다. 성공/실패별 미리보기·실제 이유·저장 재생·실패 재시도를 연결했다. 새 팩 catalog-companion-outcome-1·동행 runtime catalog-companion-outcome-1·계승 catalog-succession-9, 계약0.7.0·schema6/7/8·단독 runtime3 유지, 이전 팩 fixture v17 고정.

보호 약속은 여전히 미승인이며 선언·위반 효과를 추가하지 않았다. 이번 신뢰 시스템 진행을 막는 질문으로 두지 않는다. 상세 [결과 기반 관계](relationship-outcomes.md). 추정93%, 다음은 D09 가변 분량·두 회차약15분 실측/전체 검증이다. 아래 고정+10·구조 전용 이탈·약속 정책 대기는 과거 단계다.


2026-10-29 다음 단계 요청으로 기존 확정 회복 규칙을 제품에 연결했다. 출처는 기획안 v1.2 문단93~94·155, 기술 설계 v0.2 회복 절과 affect>=50 회복 예외다. 미정 D01 전체 추천·D03 약속/파견을 승인한 것으로 취급하지 않는다.

## 게임에서 가능한 것

동행 회차의 E04/E11에서 단독 추가 휴식 대신 물자 양보를 제공한다. 정비/양보/상처 처치/주변 또는 배낭 정리, 총4개다. 양보는 물자1 소모, 체력+10, 스트레스-5, 신뢰+10이며 상한을 적용한다. 치료는 불가하다. 물자가 없으면 양보를 이유와 함께 잠그고 무자원 정비를 유지한다. 단독 회차는 기존4개·추가 휴식 그대로다.

동료 affect<50은 정비를 권하며 affect>=50은 양보를 권한다. 물자 없으면 정비로 넘긴다. 이것은 회복에 명시된 중앙값 예외이며 다른 사건의 중립 정책을 결정한 것이 아니다. 추천과 다른 선택을 해도 이번 단계에서는 신뢰 불이익이나 협력 보너스를 추가하지 않는다.

확인창에 비용·회복·신뢰의 예상 변화를 표시하고, 결과에 상한 적용 후 실제 증감과 이유를 남긴다. 예: 신뢰95→100은 +5다. 실행 때 한 번만 반영하고 결과 확인/재접속으로 다시 올리지 않는다. 동료 신뢰의 초기 입력은 보존하며 현재 신뢰만 변한다.

## 구현과 콘텐츠

recovery behavior의 choice=share를 허용했다. 기존 순수 recovery 엔진에서 행동과 결과를 계산한다. 신뢰 상한 계산은 미리보기와 실행이 같은 함수를 사용한다. 역사 기록에 선택적으로 trustChange(before/after/reason)를 추가하고 기존 계약0.6.0의 changes/trustReasons로 변환했다. 공개 타입 변화는 없다. UI는 계산 없이 추천/잠금/실제 변화를 표시한다.

E04/E11은 companion=true 조건 그룹을 추가했다. 기존 기본 그룹과 단독 문구는 보존하고 동행 상황 문구를 별도 조건으로 제공한다. 저렴한 콘텐츠 모델은 기존 수치를 복제한 일반 action 대신 recovery/share를 사용한다. 무자원 정비와 그룹4개 원칙을 유지한다.
